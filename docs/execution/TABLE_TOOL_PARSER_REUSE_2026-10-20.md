# 表格预览解析复用与等待态保护 — 2026-10-20

状态：本地持续优化，目标保持活动；不推送、不启动 CI、不部署。
不改变依赖、API、migration、canonical 数据或导出/离线协议。

## 复现与修复

前轮把预览文本设为 React deferred value，但单元格回调会随编辑模型变化。
即使文本未变，回调更新仍使 `MarkdownTablePreview` 的 `ReactMarkdown` 子树
重新执行。浏览器中对真实解析器添加透明计数包装：先更新一个回调、不改文本，
计数从 **40 变为 41**，原本应保持 40 的断言失败。该基线执行到第 14 项时失败，
前 13 项通过；其脚本尚未加入后续四个等待态用例。

现在按规范化后的展示文本及当前 scope 复用 Markdown 子元素，仅保留已挂载
预览的当前元素。单元格 context 仍传播当前值、坐标和事件；回调变化不会触发
不变文本的 Markdown 解析。浏览器回归同时断言：

- 回调变化后四个真实单元格均得到新回调标识，解析器计数不变。
- 修改 Markdown 后真实内容更新，计数增加；数学语义仍存在。

这不是全局解析缓存，不保留历史正文，也没有移除 sanitizer 或 GFM/math 配置。
没有把同步草稿解析另加一套异步状态机；编辑模型和 Markdown 文本仍同步更新。

## 旧预览的操作边界

预览追赶时，表格可能仍显示旧页/旧行列。现在：

- 禁用从旧预览进入其他单元格、键盘跨单元格导航及边缘加行列。
- 现有活动输入继续接收字符并同步 Markdown，不因追赶而卸载或丢焦点。
- Escape 退出活动输入时聚焦 Markdown，不尝试聚焦已禁用的单元格按钮。
- Apply 保持禁用，直到当前展示快照与草稿一致且真实表格结构校验通过。

测试用 promise hold 暂停特定预览的真实渲染，让竞争条件可重复，不依赖机器
速度或固定 sleep。四个新增场景覆盖连续新草稿、继续单元格输入/Enter/Escape、
等待期间改成无效 Markdown，以及原文改变后明确 Refresh。释放旧 promise
不能覆盖最新或无效草稿，也不能污染重新打开的预览。

## 性能证据边界

可重复的结论是“回调更新不再解析不变文本”，不是“所有大表长任务消除”。
可选五输入观察现在区分：

- 网格输入后 Markdown 更新的绘制观察；
- `aria-busy` 结束后的预览追赶观察；
- 实际解析器入口数。

前两项不是同一个量，不能用更早的 Markdown 绘制数字冒充富渲染已经完成。
完整合成样本、计数、long task、源码/截图摘要与门禁回执见
[独立证据](../evidence/table-tool-parser-reuse-2026-10-20.json)。
本机未节流样本不设硬件相关通过阈值，不与旧轮次直接作受控前后对比。
大表长任务仍需继续隔离分析；浏览器 JS heap 不代表服务器 RSS 或 OOM。
