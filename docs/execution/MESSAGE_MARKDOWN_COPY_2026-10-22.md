## 恢复的用户要求与编辑前证据

原任务最后三条要求指定消息顶部收藏按钮左侧：复制整条消息为 Markdown，
图片变为 Obsidian 可读取的长期公开链接，删除文件后失效；SVG 安全转换，
其他类型附件忽略。原任务的表格发布已完成，不重复发布。最初按本地阶段实施；
用户随后明确要求“完成后直接提交部署”，本批转入下方发布流程。

编辑前代码事实：`message-item.tsx` 的顶部操作没有整条复制；
`reader-markdown-copy.tsx` 只处理当前 DOM 选区，不能完整复制虚拟化长消息；
附件 content 依赖登录，Share 是另一个独立权限，均不能直接作为这个功能的外链。
已有 Pillow、AssetStore、AssetDerivative；没有服务端 SVG 渲染器。

## 界面与实现决定

这是已明确平台、位置和行为的 Web 局部增量，不重新设计或开展竞品调研。
采用现有纸面/石墨/海绿阅读台；领域为消息、源码、附件、引用、版本、笔记。
签名仍是“canonical 源码 → 可移植 Markdown”，不复制操作标签或虚拟化 DOM。
在现有 4px 网格和语义 token 内增加 44px 复制按钮；字体、表面和层级不变。
拒绝常驻导出卡片、另一个文件管理面板及全消息 HTML 转换，以免占位或破坏源码。
等待、成功、失败属于该消息/版本/认证代次；剪贴板拒绝时提供可选只读文本。
公开风险在按钮说明与结果中直说，不默默修改既有选区复制。

后端沿用附件对象和派生预览，不加依赖：浏览器将安全隔离的 SVG 图像栅格化，
服务器只接收有界 PNG 并用 Pillow 校验/重编码。拒绝公开 SVG XML 和服务端联网
转换。外链使用独立随机能力，不含账户/附件 ID；读取时重新检查附件、原对象、
会话与扫描状态。默认不设到期，不表示已下载的外部副本可以收回。

## 完成的实现与安全检查

- 顶部复制按钮位于收藏左侧，复用桌面/手机动作与既有 token、字体、4px 网格。
  准备、成功、失败、手动选择、键盘焦点均在消息内，不另开模态层。
- GET 取完整当前源码，现有 ReactMarkdown AST 只做定位改写；不是截取已挂载
  DOM。正文未改区域、表格、公式、代码和换行保持原源码。
- 图片显式 POST 后才公开；稳定 256-bit 随机能力绑定 attachment/source。
  整批验证、源版本冲突和匿名精确 GET/HEAD 边界有回归。删除/移除、感染、
  会话删除、对象替换/丢失均失效；仍在当前正文中使用的附件原有 409 保护不变。
- SVG 仅在隔离 Blob 图像里解码；活动结构、实体、外部资源及资源越界拒绝。
  服务器只验收有界 PNG 并重编码像素；预览映射按 attachment 隔离，防止跨账户
  共享同一原对象时借用另一方可控像素。并发存储冲突可重试，不发布半批链接。
- 登出/身份代次和消息/版本退休清除准备结果，既拦截在途请求也拦截旧文本重试。
- 单一新 migration `20261022_0053`；不改 canonical、Share、便携包/Dexie 格式。
  新 Nginx token location 不记录 raw URI access/error log，不做 proxy cache。
