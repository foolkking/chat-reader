# Reader 消息合并与删除恢复审查 — 2026-10-14

这是持续普通用户体验优化中的下一批本地源码修复。本批只检查 canonical Reader
中的手动合并和删除消息操作；不改阅读位置、消息版本、撤销机制或附件数据。
不启动服务、不登录、不做浏览器或自动化验证、不提交 CI 或部署。用户将自行
验证。本记录先于源码修改建立。

## 范围与修改前证据

源码审查确认：合并和删除的 catch 都将 `Error.message` 直接放进全局 Reader
toast；网络、5xx 或连接中断时，服务端是否已经完成写入无法从异常本身得知，
但当前文案把未知结果说成普通失败。删除操作已有保留的撤销状态；合并失败则
保留当前选择，均不应被错误提示覆盖。

## 发现与决定

| ID | 类型／严重度／置信度 | 用户影响与处理 |
|---|---|---|
| READER-MUT-ERR-01 | Defect / High / Observed (code)，渲染 Inferred | Reader 核心编辑操作显示底层异常，用户无法判断下一步。按状态提供稳定双语提示。 |
| READER-MUT-RECOVERY-02 | Defect / High / Observed (code) | 未知合并／删除结果可能已经落库，立即重试会重复改变正文或造成误操作。改为要求先刷新 Reader 核对，再决定重试。 |

## 实现边界

- 不自动重放合并或删除，不新增请求、轮询或幂等协议。
- 不清空合并选择；删除失败仍保留原有状态和现有撤销路径。
- 保持现有位置恢复、版本推进、附件保留和 undo 语义。
