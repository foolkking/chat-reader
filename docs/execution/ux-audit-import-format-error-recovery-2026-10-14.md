# 导入格式设置错误恢复审查 — 2026-10-14

这是持续普通用户体验优化中的下一批本地源码修复。本批只检查用户设置中的
“我的导入格式”；不启动服务、不登录、不做浏览器或自动化验证、不提交 CI
或部署。用户将自行验证。此记录先于应用源码修改建立。

## 范围与修改前证据

范围包括格式列表读取、版本历史读取、个人名称或自动识别状态更新。

可能是英文服务端 detail、传输错误或实现细节。

## 发现与决定

| ID | 类型／严重度／证据 | 用户影响与处理 |
|---|---|---|
| IMPORT-FORMAT-ERR-01 | Defect / Medium / Observed(code) | 三种读取／保存失败都暴露 API 或浏览器原始异常，且没有解释用户下一步。改用稳定的中英文提示；已载入列表、名称草稿及当前再次操作能力保持不变。 |

错误文案仅使用操作类别和 HTTP 状态做有限分流：无权限／会话失效、记录不存在、
并发冲突、输入被拒、请求频率限制与暂时不可用。未知网络或服务端错误使用通用
恢复提示，不呈现原始异常。读取错误保留原有重试按钮；更新失败保留名称输入，
用户可再次执行原操作。

## 实现边界

- 不改变 API、缓存键、读写顺序、React Query 重试策略或无效化范围。
- 不自动重放保存操作，不把未知写入结果说成失败或成功的确定事实。
- 不清空用户输入；不改变格式状态、权限或历史版本行为。
- 不新增依赖、测试预算或服务器资源消耗。

## 实施记录

`apps/web/components/import-format-settings.tsx` 现在将格式列表、版本历史与个人
设置更新的失败映射为稳定中英文提示。已知状态按权限、格式／版本不可用、并发
变化、输入拒绝与限流区分；连接失败、超时、服务端错误和其他未知更新结果不再
