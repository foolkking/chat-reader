## 实际问题

所有样本均为合成数据，不读取账户、导入资料或生产服务器。

1. `\(|x|\)` / `$|x|$` 中的竖线原先被当作列边界，二列表格变为四列。
   直接换成 GFM 的 `\|` 又会把单竖线绝对值变成 TeX 的双竖线范数，不能这样修。
2. 代码内的连续反斜杠原先一律按单个转义移除，偶数反斜杠也会丢掉一个。
3. 图片 alt、引用标识中的 TeX 外观文字不是公式；转义未配合修改外部定义，会
   改名引用，使原本可解析的链接失效。
4. 即使保留了正确引用身份，工具只渲染表格片段、缺少外部定义，仍会把未解析的
   TeX 外观 ID 显示成公式。这是预览错误，不是原文已经被改动。
5. 后续实测发现 `\char` 的反引号字符参数被 `\vert` 改写后会从竖线变成字母
   `v`；`colorbox` / `fcolorbox` / `raisebox` / `tag` 的文字参数也会变成错误公式。

初始增补的 48 项专项为 **43 通过 / 5 失败**。加入引用身份回归后的 52 项为
**51 通过 / 1 失败**。字符码/文字参数分别留下 **20 项 / 19 通过 / 1 失败**
的中间基线。它们不是同一次全量运行，不相加成“独立失败数量”。

## 修改

### 有界、保守的单元格转换

- 明确闭合的行内公式拥有内部竖线，不再制造额外列。
- 可确定的裸单竖线写成 `\vert `；已存在的 `\|` 仍是范数。使用真实共享
  GFM/math/sanitize 渲染链比较 MathML，不只比较源字符串或公式数量。
- 代码/链接目的地/图片 alt/引用 ID 不套用可见公式改写。
- 连续反斜杠按成对消费，只有实际 GFM 转义被解码；覆盖 0–8 个反斜杠的
  原样文本、再次规范化和实际代码渲染。
- 原始引用 ID 含裸竖线时，单改表格会使其与外部定义不一致，故拒绝猜测，
  不扩大操作范围到外部定义。
- 不完整公式、文字/宏/数组前导声明等复杂上下文及上述字符码/文字盒参数
  不能安全改写时拒绝处理。不是通用 TeX 解析器，不承诺所有公式一键修复。
- 竖线编码的字节膨胀预先纳入 1 MiB 上限；超限整次拒绝，不截断正文。
- 没有改 Reader v5 数学策略、服务器接口、依赖、消息存储或导出合同。

### 只读引用预览上下文

复用已经直接依赖的 CodeMirror Markdown 解析器，不另增解析器或自行猜 ID：

- 每个冻结原文快照只读取一次，不在每次改单元格时重扫全文。
- 最多 1 MiB UTF-8 源码、256 条定义、32 KiB UTF-8 投影。
- 只提取实际 LinkReference 的标签与目的地；代码围栏/缩进代码中的示例不算定义。
- 容器内或换行后的目的地由真实节点范围提取，不复制引用/列表前缀。
- 保留标签/目的地拼写和重复定义顺序，由共享 GFM 渲染器决定匹配与 first-wins。
  不需要的链接标题仍原样留在表格外，不进入惰性预览投影。
- 投影仅追加到预览输入，绝不混入可编辑 Markdown、规范文本或最终 transaction。
- 超限、跨行标签/目的地或未投影的脚注正文只显示一条局部限制提示；
  不假装“没有引用”，也不把任意脚注正文当作 URL。
- 链接仍为惰性文字，图片仍为惰性 alt；浏览器请求监听确认零远程请求。

桌面/375px 的限制提示均不越界，应用入口仍可见。沿用既有
paper/graphite/sea-green、字体、边框层级和 4px 间距，不新增模式或常驻说明。

## 测试工具修复与边界

本轮新增的源码预览断言先暴露一个旧测试适配器限制：assistant-ui primitive
原先返回 null，因此虽然工具表格用的是真实渲染链，背后的源码预览并没有实际
渲染该分支。现在适配器把原文送入真实 ReactMarkdown/shared renderer core。
这是测试工具修复，不把旧空适配器当成生产预览缺陷；也不宣称已经验收真实
assistant-ui 包、Next 路由或认证 Reader。

随后引用上下文场景确实复现工具预览多出公式；修复上下文后通过。一次中间运行
还因新增测试把 Locator 错写成函数而失败，已修正；不算产品缺陷。原始失败
日志保留在本任务临时目录，证据分别列出，不把失败改记为通过。
