# 后续 UX 审查：批注恢复与大表格预览

2026-10-09；在本轮附件发布的完整 CI 等待期间进行。此报告先于任何后续产品修改。

## 1. 范围与证据

本批接续全站普通用户检查，聚焦阅读后的批注／精选笔记，以及 CSV/TSV 附件。
平台是桌面和手机 Web，使用现有纸面／石墨色／海绿色设计体系。优先降低误操作、
错误恢复成本和浏览器工作量，不新增依赖、不调整 Reader 锚点或离线数据格式。

- 阅读当前组件、repository 和已有同类恢复界面。

  checkout 差异。并发顺序由受控 Promise 指定，repository、React hooks 是测试替身。
- 计算真实组件返回的 React element 数量；**不是已挂载 DOM、CPU、RSS 或手机耗时测量**。
- [复现结果](ux-audit-followup-annotations-tables-2026-10-09-evidence/probes.json)和
  [复现脚本](ux-audit-followup-annotations-tables-2026-10-09-evidence/probe.mjs)包含六份

本批没有新增浏览器执行、截图或无障碍符合性验收；未观察到的视觉、真实调度和性能

## 2. 结论

最值得继续做的是让批注在局部读取失败时仍能用，并让每个失败有明确的恢复入口。
同一面板的重叠刷新还可能让迟到的旧结果覆盖新结果，造成内容“退回去了”的表现。
批注批量操作目前对同一组选择使用不同范围，应先统一语义并解释隐藏的选择。
CSV 超列数时直接丢整行是内容呈现缺陷，不只是性能问题。
表格已有解析记忆化，但仍一次性建立所有数据格，需要独立限制解析量和显示量。
这些问题可以沿用现有组件和状态模式处理，暂时不需要更换解析库或引入更重的 Viewer。

## 4. 发现

### STATE-ANN-01 · 笔记或冲突读取失败，会挡住成功读到的批注

- 类型／维度：缺陷；状态覆盖、错误恢复。
- 严重度：High；工作量：M。
- 可信度：Observed（源码＋提取回调）；界面实际呈现 Inferred。
- 位置：[annotation-workspace.tsx](../../apps/web/features/annotations/annotation-workspace.tsx#L139)、
  同文件第 159、168、599 行；[notebook-view.tsx](../../apps/web/features/annotations/notebook-view.tsx#L33)。
- 证据：`reload` 用同一个 `Promise.all` 等三个读取；任一拒绝，三个 setter 均不执行。
  单独让 notebook 或 conflicts 失败时，成功返回的批注都未发布。首次 effect 是
  `void reload()`，同步事件只吞错。列表空分支固定显示“暂无批注”；Notebook 的
  notebook 仍为 null 时，草稿加载不会启动，`loading` 保持 true，重试分支不出现。
- 对人的影响：读者不能区分“确实没有批注”和“这次没读到”；笔记辅助数据故障会扩大为
  批注也不可用。关闭重开仍可能重复同一失败。
- 建议：批注、笔记、冲突各自维护读取状态，独立发布有效结果；首次失败提供“重试读取
  批注／笔记”，刷新失败保留同一合法访问范围的旧内容。权限失效不继续显示缓存，
  冲突状态未知时不当作零冲突、不开放依赖它的覆盖动作。读取不自动重放写操作。
  现有 [ConversationList](../../apps/web/features/conversations/conversation-list.tsx#L214)
  已有保留缓存＋局部重试的产品先例。Offline `getNotebook` 首次会创建本机占位记录，
  不应把整个 repository 调用泛称为纯 GET；不改变这个现有语义。

### STATE-ANN-02 · 迟到的旧刷新可覆盖较新结果

- 类型／维度：缺陷；数据新鲜度、错误预防。
- 严重度：High；工作量：M。
- 可信度：Observed（源码＋受控 Promise）；真实浏览器发生频率未知。
- 位置：[annotation-workspace.tsx](../../apps/web/features/annotations/annotation-workspace.tsx#L139)。
- 证据：先发旧读取，再完成新读取，最后放行旧读取；实际 setter 顺序为
  `synthetic-newer → synthetic-older`。当前回调没有本次打开／conversation／repository
  的存活和请求代次判断。多个写后刷新和同步事件都调用它。
- 对人的影响：刚看见的新批注／笔记可被旧结果替换；随后按旧 revision 操作还可能遇到
  本来可以避免的冲突。此证据**不证明服务端数据被覆盖或跨账户泄露**。
- 建议：独立读取加当前作用域和代次保护，关闭、换会话／数据源、认证代次变化后拒绝旧
  回调；确认写成功的本地状态不得被更早请求降级。只增加常数大小的状态，不增加轮询。

### DATA-ANN-01 · 同一组批量选择，在不同操作中含义不同

- 类型／维度：缺陷；选择范围、错误预防。
- 严重度：Medium；工作量：M。
- 可信度：Observed（源码＋提取回调）；用户是否误解尚无可用性研究。
- 位置：[annotation-workspace.tsx](../../apps/web/features/annotations/annotation-workspace.tsx#L434)、
  第 467、475、554 行。
- 证据：选中两条、筛选后只剩一条可见；“应用样式”和“删除”处理两条，“加入精选笔记”
  只处理可见的一条。删除确认确实写“删除 2 条批注？”，不是无确认删除，但没有说明
  其中一条已经被筛选隐藏。选择的清理 effect 只跟随全集，不跟随可见列表。
- 对人的影响：同一个“已选”数量无法预测操作范围；加入笔记可能少一条，修改样式或删除
  可能涉及当前看不见的项目。
- 建议：保留跨筛选选择，但所有批量操作采用同一组当前有效已选项；显示“已选 2 条，
  其中 1 条不在当前筛选中”，提供查看／清除已选。删除前再确认当前范围，不静默清选择。
  书签不能改样式、已在笔记中的引用不重复添加，须另报适用数，不能伪装成全部完成。

### DATA-CSV-01 · 宽表行被静默舍弃，数据行甚至会变成表头

- 类型／维度：缺陷；数据完整呈现、超限状态。
- 严重度：High；工作量：M。
- 可信度：Observed（真实解析器输出）；界面呈现 Inferred。
- 位置：[attachment-table-policy.ts](../../apps/web/features/attachments/attachment-table-policy.ts#L17)、
  [attachment-viewer.tsx](../../apps/web/features/attachments/attachment-viewer.tsx#L375)。
- 证据：两行各 257 列返回零行；257 列表头后跟一行 `short,value`，仅返回后者。
  Viewer 对零行显示“空表格 · 没有可显示的行”，否则把返回的第一行当表头。
- 对人的影响：非空文件会看似空文件，或者列标题失真。Raw／下载仍可用，所以这不是
  原文件丢失，也不宣称是不可恢复的数据损坏。
- 建议：解析返回明确的范围／超限原因，保留行顺序和真正的表头；达到列／字段／总量
  上限时要么展示明确标注的前缀，要么回退 Raw，绝不跳过宽行再续接后面的短行。
  提示应为“表格超出预览上限，原文件未改变”，并保留“查看原文／下载”可用路径。

### PERF-CSV-01 · 解析有上限，但整个表格仍一次性建立，字段预算也未生效

- 类型／维度：性能改进机会及既有预算未落实；数据展示、资源开销。
- 严重度：Medium；工作量：M。
- 可信度：Observed（源码＋React element 计数＋计算）；CPU／内存影响 Inferred。
- 位置：[attachment-viewer.tsx](../../apps/web/features/attachments/attachment-viewer.tsx#L375)、
  [attachment-table-policy.ts](../../apps/web/features/attachments/attachment-table-policy.ts#L1)。
- 证据：100 个数据行 × 64 列的真实组件返回 6,400 个 `td` 和 6,400 个 `span`；
  每行、每列均同步 map，未分页或虚拟化。当前 10,000 数据行 × 256 列对应
  **2,560,000 个数据格的计算上界**，并非执行过这个最大浏览器样本。65 KiB ASCII
  单字段全部保留；文档旧称 64 KiB 字段／250,000 单元格预算，当前实现未全部执行。
- 对人的影响：文件仍被接受时，读者可能需等待大量不可见单元格建立，弱设备更有风险。
  具体耗时和峰值必须实际测量，不以元素数冒充性能分数。
- 建议：分开限制输入解析、总单元格／字段和当前呈现工作量。先评估简单分页与现有
  virtualizer，优先可预测的低成本方案；保留真实行号、固定表头、原文和超限说明。
  不因显示截断更改原始文件；不引入大型电子表格编辑器。与 DATA-CSV-01 同批验证。

## 5. 建议执行顺序

1. 完成本轮冻结源码的全部 CI／独立镜像验收与安全部署；失败时只修发布阻塞。
2. STATE-ANN-01 与 STATE-ANN-02：同一读状态所有权批次；失败、乱序、切换、权限专项。
3. DATA-ANN-01：所有批量操作范围和确认语义一致；验证筛选与未完成写入的组合。
4. DATA-CSV-01 与 PERF-CSV-01：保真和预算一起处理，先保住表头／行序，再缩小呈现窗口。

后续本地实现仍不自动提交 CI／部署，等待用户再次明确要求。

## 6. 保留什么

保留安静的阅读位置自动保存、完整轮次、真实 DOM 锚点、现有 PDF 两个并发渲染／画布
预算、图片按需解码、媒体不自动播放，以及当前 JSON／Office／Blob 恢复修复。
批注写操作已有 revision／离线冲突防线，不以本次客户端现象否定其服务端保护。
保留正常筛选、表格 Raw、下载权限和现有界面 tokens；不趁审查重做视觉体系。
