# 附件查看器会话状态隔离审查（2026-10-14）

## 范围与修改前证据

本记录先于本批源码修改建立，范围是统一附件查看器外壳在连续打开不同附件、
图片画廊切换以及同一附件资产替换时的本地查看状态。按用户当前要求，本批不启动
服务、不登录、不运行浏览器或自动化验证、不提交 CI、不部署。

源码证据：

- `AttachmentViewerProvider` 在已有查看器外壳仍挂载时通过 `setSession` 打开新会话；
  `AttachmentViewerShell` 中的 `activeKey`、`mode` 和 `maximized` 只用
  `useState` 的初始值读取一次，未随新会话身份重置。
- `ViewerBody` 只使用 `item.itemKey` 作为 React key。若同一查看条目对应的资产
  被替换，JSON 的 Raw/格式化选择等子视图状态仍可能沿用旧资产。
- 该状态复用不会修改服务器内容，但会让用户打开新附件后停留在错误的附件、
  错误的显示模式或旧的最大化状态，增加误读风险。

## 处理决策

为查看会话建立稳定的本地身份：来源、范围、访问主体、附件条目及初始条目共同
参与会话边界。会话身份变化时重置当前条目、初始显示模式、最大化状态和派生媒体
指标；渲染器再使用附件 ID 加资产 SHA-256（无哈希时回退内容 URL）作为 key。
这样只清理本地查看状态，不增加请求、解析、Worker 或渲染预算。

## 本地实现与边界

已在 `AttachmentViewerProvider` 中为每次 `open()` 分配单调递增的本地
`viewerSessionId`，并以该 ID 作为 `AttachmentViewerShell` 的 React key。
因此连续打开新附件时会重新初始化当前条目、初始显示模式、最大化状态和会话内
媒体指标，不会继承上一个查看器外壳的状态。`ViewerBody`、图片缩放容器和外壳
指标清理进一步使用附件 ID 加资产 SHA-256（无哈希时回退内容 URL）的身份，
同一附件 ID 的资产替换也会重新挂载对应渲染器。

当前会话内的图片上一张/下一张、Raw/格式化切换和显式最大化仍由用户操作控制；
只有打开新会话或资产身份变化时才重置。下载、权限、PDF 页面读取和附件内容合同
保持不变。

本批不宣称浏览器焦点、布局、真实调度、CPU/RSS 或运行时验收结果；用户可自行验证
连续打开不同类型附件、同一附件替换资产及图片画廊切换。
