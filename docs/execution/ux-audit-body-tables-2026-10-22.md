## 1. 范围与证据边界

目标用户是在 Reader 阅读 AI 对话、遇到宽表或错误列后需要快速修正 Markdown 的用户。
目标不是建立电子表格，而是让正文表格好读、让某一行或某一列容易修改。

本次已做：

- 阅读当前共享 Markdown renderer、Table tool、纯转换接口、Reader 编辑入口及权限。
- 使用 Codex **内置浏览器**查看四个 GitHub 项目及其官方资料；没有使用 web search。
- 实际打开 BlockNote、Milkdown、TOAST UI 的官方运行示例。
  在 BlockNote 打开列菜单；在 Milkdown 打开列操作栏；
  在 TOAST UI 切换 Markdown / WYSIWYG 模式。未执行示例的删除命令。

本次没有：

- 启动 Chat Reader，测量实际正文表格的列宽、横向滚动或触摸行为。
- 访问生产数据、真实账户、Share 链接或用户文档。
- 完成跨浏览器、375px、键盘、辅助技术、性能或服务内存验收。

因此，代码结构可以标为 **Observed (code)**；当前正文在特定内容下的视觉问题只能
标为 **Inferred**，不能把第三方示例的体验当作 Chat Reader 的验收结果。
浏览器截图仅在本次会话中查看，未保存为仓库证据文件。

前一轮表格收尾针对的是源码工具既定范围；它不构成正文展示、正文直达编辑或删列

## 2. 结论

**用户指出的两个实现缺口都存在。**

1. 普通正文与可编辑工具预览复用语义解析链，但使用不同的表格展示组件。
   之前的单元格编辑、分页和四边 `+` 只接在工具预览上。
2. 现有转换合同和工具界面没有删除行、删除列，也没有针对当前行列的结构菜单。

最适合本项目的组合是：

- **BlockNote：** 选中行列后出现手柄菜单，明确操作对象。
- **Milkdown：** Markdown 与可视表格保持对应，但不因此替换本项目编辑器。
- **TOAST UI：** 用简洁的表格上下文菜单补足插入、删除，不堆一整排常驻按钮。
- **Tiptap：** 将“当前列左插、右插、删列”等做成明确命令，供 UI 与测试共同调用。

推荐沿用现有组件和源码保存链路，不引入上述编辑器依赖，不复制其源码，
不更换 Markdown renderer，不把整个 Reader 改造成富文本编辑器。

## 3. 当前实现的定向发现

| ID | 维度 | 严重度 | 置信度 | 工作量 |
| --- | --- | --- | --- | --- |
| TABLE-01 | 任务入口 / 阅读与编辑衔接 | Medium | Observed (code) | M |
| TABLE-02 | 表格结构编辑 / 操作完整性 | High（针对删列任务） | Observed (code) | M |
| TABLE-03 | 正文信息呈现 / 宽表可读性 | Medium，待测量 | Inferred（基于代码及用户反馈） | M |

### TABLE-01：工具预览能力没有接入正文表格

- **位置：** `apps/web/features/conversations/markdown-renderer.tsx:255–269,315–387`；
  `apps/web/features/conversations/conversation-reader.tsx:1835–1865`。
- **证据：** 正文 `table` 返回普通滚动容器及 `<table>`；
  `MarkdownTablePreview` 单独使用可编辑单元格组件。普通 `MarkdownRenderer`
  没有表格编辑回调。Reader 已有按消息和块打开源码的入口，但没有表格级范围入口。
- **影响：** 工具中的体验改善不会自动改善用户平时阅读的表格；
  用户仍需自己找到源码中的相应表格。
- **建议：** 正文先改善阅读布局，再给有 canonical 编辑能力的上下文提供
  “编辑表格”，精确打开现有工具。没有可信源码映射时不能靠相似文本猜测目标。

### TABLE-02：没有删除目标行列的完整操作

- **位置：** `apps/web/features/editing/markdown-table-tools.ts:14–19,240–259`；
  `apps/web/features/editing/markdown-table-dialog.tsx:394–413,508–522`。
- **证据：** `MarkdownTableAction` 只有 create、normalize、replace、add-row、
  add-column。工具内的 `addEdge` 只在四周增加行列，没有删除命令或行列菜单。
  虽然用户可以手动改 Markdown，但不等于存在方便的删列功能。
- **影响：** 删除中间某一列必须自行修改表头、分隔行及每一条数据行；
  分页表格中尤其容易漏掉当前页外的行。
- **建议：** 选中具体列/行，显示目标高亮，使用上下文菜单插入或删除；
  全表结构操作必须作用于完整草稿，而不是当前预览页。

### TABLE-03：正文仍缺少面向不同内容的宽度策略

- **位置：** `apps/web/features/conversations/markdown-renderer.tsx:257–269`；
  `apps/web/app/globals.css:777–782`。
- **证据：** 正文使用 `w-max min-w-full` 与横向滚动，单元格没有独立的宽度/换行策略；
  现有全局样式主要是表格最大宽度、交替底色和悬停效果。
- **推断边界：** 这提示长说明列可能拉宽全表，但本次没有在实际 Reader 测量，
  不能断言所有表格都有问题，也不能直接指定一个对所有列生效的固定宽度。
- **建议：** 用长说明、短数字、公式、链接混合 fixture 实测后制定正文布局，
  不再只验收工具弹窗的截图。

## 5. 推荐的最小产品方向（待确认）

### A. 正文：先好读，不默认进入编辑态

1. 改造**正文真实使用的**表格展示，而不只改 `MarkdownTablePreview`。
   长说明允许合理换行，短数字保持易比较；长链接、代码和公式有可读的溢出处理。
   必要时保留表格内部横向滚动，不能把整页撑宽，也不能省略正文内容。
2. 表格右上角保留轻量入口：`展开`；可编辑上下文额外有 `编辑`。
   桌面可淡化操作外观，但触摸及键盘用户不应必须先悬停才能发现入口。
3. `展开` 打开按需的阅读视图，一次只打开一张表格；
   不为每个正文表格常驻第二份大 DOM，不给所有单元格挂编辑器。
   巨表展开需要明确渲染边界，不能撤掉现有 Reader 窗口化。
4. 编辑权限沿用现有能力与调用上下文。当前离线 data source 的
   `canonicalManagement=false`，本轮不扩展离线写入；Share 保持只读。
   普通附件预览、批注和其他 Markdown 消费方不能凭共享 renderer 获得修改原文的入口。
5. 保留真实正文节点的 source 属性及 Reader 锚点；展开层不参与原文批注或进度采集。
   关闭后恢复触发点，不把布局变化误记为主动阅读滚动。

这不意味着阅读时自动修复非法 Markdown。无法被 GFM 识别的文本表格仍由用户
主动进入工具规范化，保存之后正文才显示新版本；不能渲染时偷偷改源文。

### B. 编辑：选中哪一列，就操作哪一列

使用现有 Table tool，不恢复原先多个“规范/加行/加列”模式。
只保留标题“表格工具”、可视表格、Markdown 和必要状态。

- **列手柄：** 点击后高亮当前列，菜单只有 `左侧插列`、`右侧插列`、`删除此列`。
- **行手柄：** 点击后高亮当前行，菜单为 `上方插行`、`下方插行`、`删除此行`。
- **四边 `+`：** 保留作为快速增加入口，不用边缘 `−` 代替明确的目标选择。
- **删除反馈：** 在工具草稿中删除，短提示 `已删除第 3 列 · 撤销`；
  不立即保存服务器，不为每次局部删除再弹多层确认。
- **撤销：** 结构删除在工具内必须可撤销；不能只依赖点击 Apply 后的源码撤销。
  局部历史应有字节上限，不能每次键入都复制整张大表。
- **边界：** 至少保留一列；固定保留 GFM 表头结构，不把删除表头静默变成提升首行。
  删除最后一条数据行可以留下只有表头和分隔行的合法表格。
- **全表一致：** 删列同步修改表头、分隔行、全部数据行和对齐声明；
  分页只限制展示，不限制修改范围。删行定位使用完整草稿的行号，不能误删另一页。
- **移动端：** 单击即可选择行列；菜单/紧凑底部操作层可触达，
  交互区域沿用项目 44px 目标，不能依赖右键、悬停或难以发现的长按。

### C. 正文到工具：精确直达，但不另建保存系统

正文 `编辑` 应携带消息身份、消息版本、块内表格范围以及可验证的源码映射，
进入现有源码工作区并直接打开该表格。**不能只按“第几个表格”或相似文本定位。**

需明确处理：

- 渲染块内 offset 与消息 canonical source offset 不是同一个坐标系；
  继续使用已有映射及编码约定，不能把 HAST offset 直接当全消息偏移。
- 同一消息的源码工作区已经打开时，应定位并打开表格工具，
  不能复用当前“再次打开同一消息就关闭”的切换行为。
- 已有未保存源码草稿时，以草稿为准重新验证；对不上时保留草稿并提示，
  不能用服务器旧文本覆盖，更不能为方便定位丢弃草稿。
- 原消息版本变化后拒绝套用旧范围；继续沿用失效、冲突及保存保护。
- Apply 仍是一个 CodeMirror transaction；正常保存/版本流程不变。
  关闭工具未 Apply 不改源码，工具内撤销与 Apply 后源码撤销是两个明确层次。

## 6. 实施优先级与验收

1. **正文展示专项。** 先建立实际 Reader 合成 fixture，再调整共享展示组件。
   验证正文，而非只截工具弹窗；覆盖 Owner、Share、Offline 和其他共享消费方。
2. **删列/删行。** 补纯转换命令与工具行列菜单，验证全表范围、即时 Markdown 同步、
   删除撤销及 Apply 后一次撤销。首列/中间列/末列必须分别覆盖。
3. **正文精确直达。** 接入权限、源映射、已有草稿和版本变化，避免错误表格被编辑。
4. **有界回归后收尾。** 不再扩展表格产品范围，不顺手增加排序、公式、合并单元格、
   拖拽重排、持久化列宽、Excel 导入或新的后端接口。

最低验收集：

- 375px / 平板 / 桌面、明暗主题，长说明、数字、公式、代码、超长链接与空表头。
- 正文宽度、表格滚动、键盘菜单、触摸选择、焦点返回及阅读锚点实际测量。
- 多张相同内容的表格仍能选对；引用/列表内表格、CRLF、Unicode、
  转义竖线及引用定义保持原有语义。
- 删除当前页之外的数据行、跨全部分页删列、最后一列保护和零数据行输出。
- 编辑中的 IME 不被结构操作吞掉；无效 Markdown/解析等待时不能应用旧预览。
- 工具内撤销、取消、Apply、源码一次撤销、保存冲突与消息版本变化。
- 验证正文查看不会新增保存请求；只读访问没有写入入口；
  大表不因常驻多个编辑器/展开副本而新增无界占用。

本次仅改研究文档，因此没有运行产品测试，不将旧测试结果算作上述验收。
当前没有新 migration、依赖、数据合同或部署变更。后续实现需按实际影响运行
Web lint/typecheck/build、表格专项及 Reader/Share/Offline 浏览器回归。
