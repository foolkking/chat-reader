# 噪声匹配审查 — 2026-10-25

## 1. 范围与证据

本轮只审查噪声匹配链路：内置检测器、自定义字面规则、规则试运行、
候选保护以及后续规则审查入口。目标用户按混合受众处理；本轮取舍为
精确率优先，不确定候选继续可见但受保护。

证据来自当前源码和 2026-10-25 的合成 SQLite API 回归测试。没有读取真实
对话正文、导入资料、Cookie、凭据或 Share token；没有进行 web search、生产
PostgreSQL、认证 Reader/Share/Offline 或部署验收。基线共 97 项相关测试，
全部通过。证据清单见同目录的 `ux-audit-noise-matching-2026-10-25-evidence/`。

## 2. 结论摘要

当前匹配器已经具备较强的安全基础：精确、规范化和受限近似模式分开处理，
Markdown/代码范围会保护，近似和不确定命中不会直接进入普通删除路径，
试运行也不会写入规则。现有回归覆盖了 Unicode 偏移、边界、引用、页脚、
模糊锚点、重叠去重和例外范围。

审查发现一个会改变用户意图的实际匹配错误：规则入口和身份配置会无提示地
去掉匹配文本首尾空白。对于从正文选择的带换行、缩进或尾随空格的噪声，
试运行、保存和后续扫描可能不再匹配用户选择的原文。另有一个试运行证据
代表性问题：上下文样本只取扫描顺序中的前 10 项，单条消息命中很多次时，
用户可能看不到其他消息或其他上下文中的差异。

本轮优先修复首尾空白保真，并让试运行样本按消息分散、同时标示匹配模式，
让用户能更快发现过宽或近似规则。不会放宽保护规则，也不会新增正则或
LLM 匹配。

## 3. 快速收益

1. 保留 `match_value` 的原始首尾空白；仅拒绝全为空白的规则。
2. 试运行样本最多 10 项，但每条消息最多贡献 3 项，避免单条消息占满样本。
3. 在样本中显示 `RAW_EXACT`、`NORMALIZED_EXACT`、`BOUNDED_FUZZY` 等模式；
   近似候选仍保持受保护。

## 4. 发现

### NOISE-01 · 字面规则静默裁剪首尾空白

| | |
|---|---|
| **维度** | 匹配正确性、输入与表单 |
| **严重性** | **High** |
| **置信度** | Observed (code) |
| **位置** | `apps/api/app/services/cleanup_learning.py:133-134`；`apps/api/app/services/cleanup_rule_identity.py:15-17`；`apps/web/components/cleanup-rule-editor.tsx:134` |
| **工作量** | S |

**证据。** 规则配置在进入试运行和保存前对 `match_value` 调用 `.strip()`；
前端保存结果比较也对草稿匹配文本调用 `.trim()`。同一编辑器文案却声明
“文本按字面匹配”。因此 `"\nNOISE "` 会被当成 `"NOISE"`，而不是保留用户
选择的原文范围。

**为什么重要。** 用户可能从消息中选择带缩进、换行或尾随空白的导出噪声。
规则看似试运行成功，但命中的跨度已经扩大或改变，可能把普通正文一并纳入
候选；规则历史和用户看到的匹配文本也不再代表真实匹配条件。

**建议。** 名称继续规范化；匹配文本保留原始字符串，只拒绝空字符串或
全为空白的值。前端以精确字符串比较保存结果，并增加首尾空白回归测试。

### NOISE-02 · 试运行上下文按扫描顺序截取，代表性不足

| | |
|---|---|
| **维度** | 系统反馈、错误预防 |
| **严重性** | **Medium** |
| **置信度** | Observed (code) |
| **位置** | `apps/api/app/services/cleanup_learning.py:142-230`；`apps/web/components/cleanup-rule-editor.tsx:116-124` |
| **工作量** | M |

**证据。** API 固定最多返回 10 个样本，并在扫描循环中遇到命中后立即追加。
前端也明确提示“最多 10 项上下文”。当前查询按消息 ID 顺序扫描；一条消息
包含大量命中时，前 10 项可能全部来自同一条消息。

**为什么重要。** 用户在保存宽泛规则前只能看到局部证据，可能错过其他角色、
其他消息或说明性上下文中的误匹配。对精确率优先的工作流，样本应帮助用户
发现差异，而不是只证明第一条消息能命中。

**建议。** 保持总量上限 10，但每条消息最多贡献 3 项，按消息轮询填充；
样本同时显示实际匹配模式和保护状态。这样不扩大匹配范围，只提高试运行
证据的覆盖。

## 6. 当前做得好的地方与本轮不改

**做得好的地方。** `EXACT`、`NORMALIZED`、`APPROXIMATE` 有清晰分支；
近似候选和不确定结构默认 `PROTECTED`；Markdown 代码、链接、公式等范围
会保护；试运行绑定配置和版本且不写入规则；现有扫描/审查/应用流程保留
源版本和差异确认。

**本轮不改。** 不新增正则、跨消息匹配、LLM 判断或自动删除；不改变内置
结构检测器的保护策略，不调整已有近似距离上限，不改 schema、migration、
导入管线、离线包或 Reader/Share/Offline 数据合同。
