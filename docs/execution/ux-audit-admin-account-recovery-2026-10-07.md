# 用户管理操作与返回恢复审计 — 2026-10-07

本轮继续持续优化目标；前五批未提交改动保留。范围是 Root 用户目录、账户
访问操作、操作后返回列表和失效详情；使用当前工作区源码，下一步在独立
PostgreSQL/API/worker 与浏览器中复现。尚未观察运行结果的外观不作为已验证事实。
不部署、不清理用户资料，不调整默认 Skill、Context 文件或账户授权规则。

## 最需要处理的三点

1. 管理员已经收到状态操作成功的反馈，但全部按钮还等待后台读取，网络缓慢
   时无法继续。界面应先显示服务器确认的账户状态，再独立刷新列表。
2. 筛选最后一页的最后一个账户被处理后，目录没有自动修正页码，必须手动回
   首页；返回应保留筛选并落在有效页和可操作的账户行。
3. 已读详情再次读取失败仍展示旧账户和可操作按钮；明确的不存在／无权限要
   与暂时断网区分，避免对已失效的对象继续操作。

## 保留的行为与验证范围

Root-only API、独立审批／验证、禁用撤销会话、删除影响预览和不可撤销提示均
有明确实现，保持不变。目录已有查询隔离和常规返回定位，不引入新的持久化状态。
重置链接只保存在当前界面；资料查看仍使用只读、留审计的专用 Reader。

先运行修复前失败，再运行三种宽度、中英文／浅深色、键盘、延迟读取、真实状态
变化与分页、失效详情；同时执行原管理员专项。后端响应若有增量，运行对应
认证／访问 API 测试和真实 PostgreSQL 场景。测试不以 mock 成功替代写入，所有
故障注入及未执行项目单列。临时文件使用 C 盘独立任务目录，复用原测试集群。

这份是聚焦审计，未覆盖邀请、审计分页、全部管理员内容查看及全站视觉系统；
它们不因本批没有发现而认定完成。操作频率和真实用户满意度没有线上采样，
优先级依据可复现流程成本，不声称用户调研结论。
