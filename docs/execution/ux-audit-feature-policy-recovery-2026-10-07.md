真实基线 `feature-policy-baseline` 两项失败：分享权限实际被旧表单重新打开；
真实 PUT 200 已持久化但浏览器丢失响应后找不到核对入口。两个截图保留。
初版 `feature-policy-first` 的 10 个浏览器场景通过，包含三宽度冲突／丢响应、
读取失败、同字段二次冲突、未到服务器的保存及真实 20 秒 GET/PUT 超时。

截图评审后将 Save 移到比较结果之后，避免手机上看完比较又回滚寻找保存；
同时补上另一窗口已保存相同值的直接核对结果。合并验收 40 项通过后，截图
显示主保存按钮仍在比较区域下一屏；最终将保存和服务器选择放入同一操作行，
添加三宽度下两个按钮同时处于 viewport 的断言，11 项功能策略场景再次通过。

API 初次 9 passed / 2 failed，仅两处 SQLite 时区字符串断言错误；UTC 归一化
后 11 passed。完整本批相关 API 58 passed，含注册/能力、支持限额和真实导出
回收。实际 PostgreSQL 专项 3 passed：缓存 ORM 的竞争写入、旧部分字段并发、

没有迁移、生产变动或重新初始化已有集群。

### 最终实现

GET/PUT 增加根据白名单策略值计算的 opaque revision，不依赖可回滚默认行的
时间戳。PUT 的 `base_revision` 可选，旧部分字段请求继续保留其他配置；旧请求
不宣称获得新界面的乐观冲突保护。PostgreSQL 先串行锁定策略，再持行锁刷新
ORM 状态、比较 revision、更新和记录成功审计。响应在事务内取快照，提交成功
后才返回。首次读取／写入创建单例也串行处理；无 migration。

表单只提交改变字段。冲突保留输入，读取最新值后仅重放用户本次改动，展示
服务器和待保存值，再明确保存；二次冲突重复同样流程。用户可明确使用服务器
值放弃草稿。结果不明只提供核对读取，匹配时称“当前策略与本次提交一致”，
不推断原请求是否执行，不重复写入。不匹配则保留草稿供比较。网络读取失败
保留恢复动作；读写 20 秒有界，卸载取消与账户代际隔离，语言变化不重置表单。
