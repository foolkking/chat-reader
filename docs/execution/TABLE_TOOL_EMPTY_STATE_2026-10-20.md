## 证据与修复

[前一阶段](TABLE_TOOL_GFM_CONTEXT_2026-10-20.md)的实际截图显示：无可处理表格时，
工具虽然正确禁用 Apply，却仍显示 Markdown 标签和一块空白禁用编辑区。它占据
手机工作区、像是需要填写的字段，却不能输入。

新增正式浏览器基线在旧 **56** 个场景通过后，因该字段仍存在而失败；不把它当作
原文处理或 GFM 防护失败。

本轮只调整现有条件呈现：

- 没有原表格时不挂载假 Markdown 字段；保留单句恢复说明。
- Apply 仍禁用，并用 `aria-describedby` 关联上述原因。
- 次操作改为“返回源码”，关闭后恢复 CodeMirror 焦点；校验进行中仍可取消。
- 已识别表格的无效/未闭合草稿仍完整可编辑，保留最近有效预览和修复提示。
- 表格存在时正常编辑、边缘控件、待渲染保护、范围校验与一次 Undo 不变。

继续使用批准的纸面/石墨/海绿色、字体、4px 间距、原层级及至少 44px 操作区域；
没有新增模式、提示层或常驻说明。

## 测试假设修正

首次新增场景虽然以 375px 命名，`startWorkspace` helper 却将先前设置的视口重置为
桌面尺寸。该次 57 场景与六项门禁在原断言范围内通过，但其“手机”截图实际为
1440×900，不能算新增手机布局验收。

没有删除这次记录或把它描述成产品失败。最终改为在 helper 之后设置视口，
立即断言真实 `innerWidth`，并保存实际宽度、对话框尺寸、源码与焦点结果。
这次检查也不宣称真实触摸设备或辅助技术验收。
