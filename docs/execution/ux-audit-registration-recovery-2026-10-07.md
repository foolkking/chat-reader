## 设计与验收

沿用既有设置层级、纸白／石墨／海绿和 44px 操作。注册结果、错误和比较留在
注册策略内部，邀请列表继续保持原状态。仅冲突／失败时出现恢复说明；比较
之后主保存和使用服务器值处于同一操作行，手机不必往返寻找操作。

保留旧 mode-only 客户端；新请求 mode 可省略，仅更新明确提交字段。策略
revision 不纳入 SMTP 配置探测或更新时间，避免环境状态冒充策略编辑。旧请求
不声称获得乐观锁保护。验证与审批独立，启用只影响新账户，旧账户不追溯锁住。

真实验收覆盖三宽度／中英文／浅深色，冲突后新注册账户仍受审批／验证门槛
约束，丢响应与实际未保存的核对，二次冲突、重读失败、草稿退出和邀请保持。
API 与真实 PostgreSQL 并发验证旧模式兼容、缺 SMTP、事务审计和首次创建。

临时目录 `wkkk/chat-reader-registration-recovery-20261007`，复用已停止的独立

## 执行结果

### 已实现

Root GET/PUT 增加只覆盖四个策略字段的 opaque revision；新 PUT 可省略 mode，
只发送本次更改。旧 mode-only 请求保持兼容，但不宣称获得新客户端的乐观冲突
保护。PostgreSQL 先串行锁定，再持行锁刷新 ORM、比较基础版本。首次创建保留
部署配置中的注册模式。冲突返回 `REGISTRATION_POLICY_CHANGED`，不修改或写
成功审计；成功响应在事务内取快照后提交。无效请求与审计失败均不留下半写入。

注册表单保留本次草稿，读取当前策略后合并未改字段并显示差异，再由管理员
保存或明确采用服务器值。结果不明只读取核对，相同值不重复写入，也不猜测
是哪次请求写入。20 秒请求期限、卸载取消、账户代际保护和本区焦点反馈沿用
现有实现方式。邀请表单在策略恢复中保持挂载；语言变化不重载注册草稿。

邮件配置状态不参加策略 revision。已有验证开关未修改时不重发，SMTP 之后
不可用不会阻止其他设置保存；实际尝试启用验证仍由后端拒绝。没有改变验证、
审批、旧账户登录、邀请消费或密码重置令牌合同。
