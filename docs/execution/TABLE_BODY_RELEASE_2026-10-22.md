## CI 与部署顺序

1. 提交前复核已确认范围、证据、whitespace 和单一 Alembic head。
2. 提交并正常 fast-forward 推送，不 force push，不混入未相关缓存。
3. 验证远端精确 commit，只派发一次 `build-release-images.yml` / `master`。
4. 确认新 run 对应本次提交后，向用户报告 run 并停止；不轮询质量结果或擅自部署。
5. 用户告知通过后，独立核验同一 commit/run 的所有质量与镜像任务、原始制品
   元数据/架构/修订，再进入既有低内存备份、预检、无构建替换与运行验收。
6. 部署前重新读取真实线上版本、schema、恢复点与资源，不用过时文档代替检查；
   保留当前/直接回退镜像和新备份。不覆盖生产环境、卷或用户原文，不用 `down -v`。

正文精确直达编辑、展开查看、极大表长任务、跨浏览器和长期低内存测试仍是明确
