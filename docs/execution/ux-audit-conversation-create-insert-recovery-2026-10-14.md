# 新建对话与插入消息恢复审查 — 2026-10-14

这是持续普通用户体验优化中的下一批本地源码修复。本批只检查新建对话和
手动插入消息两个核心编辑入口；不启动服务、不登录、不做浏览器或自动化验证、
不提交 CI 或部署。用户将自行验证。本记录先于源码修改建立。

## 范围与修改前证据

范围包括表单提交失败、网络／服务端未知结果、冲突或权限失败，以及失败后
保留用户输入。

源码审查确认：两个写入入口的 catch 都直接展示 `cause.message`。这会把后端
detail、网络错误或实现文本直接放进对话框；同时网络、5xx 等写入结果未知时，
文案会把操作说成普通失败，用户可能立即重复创建或插入。两个表单的草稿本身
会保留，这是应保留的正确行为。

## 发现与决定

| ID | 类型／严重度／置信度 | 用户影响与处理 |
|---|---|---|
| CONV-EDIT-ERR-01 | Defect / High / Observed (code) | 核心写入路径暴露原始异常。按状态提供稳定的中英文恢复文案。 |
| CONV-EDIT-RECOVERY-02 | Defect / High / Observed (code) | 未知写入结果被说成失败，用户可能重复创建对话或重复插入消息。提示先检查当前对话／列表，再决定是否重试；不自动重放。 |
| CONV-EDIT-STATE-03 | Opportunity / Medium / Observed (code) | 失败后草稿已保留但界面没有明确告诉用户。错误文案明确说明输入仍保留。 |

## 实现边界

- 不改变创建、插入 API、消息顺序、阅读位置、版本或附件语义。
- 不添加自动查询、轮询或幂等协议；未知结果只提供人工核对方向。
- 保留标题、项目、用户消息、助手消息、插入位置、身份和模式等所有输入。

## 实施记录

`new-conversation-dialog.tsx` 与 `message-insert-dialog.tsx` 现在按会话过期、
权限不足、项目／锚点不存在、并发变化、输入限制和限流状态显示稳定的中英文
