# 表格工具大输入续查 — 2026-10-20

本记录在 2026-10-21 补齐，说明上一轮已实施的性能改动，不冒充修复前交付的 UX
审查。仅本地；不推送、不启动 CI、不部署。

## 实现

- Markdown 输入值立即更新；整表解析使用 `useDeferredValue`，只处理仍与当前输入
  相同的快照。网格已有模型，正常单格编辑不再重扫整表。
- 规范且有效的网格草稿只序列化被修改的物理行；UTF-8 预算按旧行/新行差额更新。
  直接编辑过原始 Markdown、无效草稿恢复或改变行列结构时仍完整序列化并检查。
  行内管道、代码、容器前缀及 CRLF 复用原有序列化器。
- 普通预览维持最多 30 条数据行、400 个挂载单元格。源表格超过 3,200 个单元格
  （包含表头和分隔行）时改用 120 个可视化单元格预算。至少显示完整表头和一行数据，
  因此 200 列表格仍可挂载 400 个单元格；120 不是无条件上限。
- 50,000 个源单元格和 1 MiB 原文限制不变，分页不截断 Markdown 或最终应用内容。
  权衡是大表需要更多页；没有新增全局缓存、Worker、服务器接口或依赖。

## 本地观察，不是性能验收

Windows、Chrome 155.0.8059.82、未节流的 headless、实际源码工作区、全合成数据。
每种输入五次；下面是中位数。网格“更新帧”指按键后 Markdown 更新的下一帧，
“预览就绪”另等最新表格完成结构检查。“源码到表头”指编辑 Markdown 后新表头
显示的下一帧，不是 textarea 字符首帧延迟。

| 表格 | 挂载单元格 | 网格更新帧 ms | 预览就绪 ms | 观察全程长任务数 | 源码到表头 ms |
| --- | --- | --- | --- | --- | --- |
| 10 列 × 4,000 行，自适应前→后 | 310→120 | 75.1→61.2 | 114.5→93.3 | 5→1 | 81.1→58.6 |
| 200 列 × 248 行，自适应前→后 | 400→400 | 54.5→51.3 | 96.6→93.0 | 0→0 | 86.7→82.0 |

**2026-10-21 口径更正：** 原表把长任务列称为“网格长任务数”，但当时观察器在网格
输入后没有立即停止，还覆盖 Markdown 输入和最终显式 GC。现只更正列名，原始
数字、文件和门禁不变；无法从旧记录把这些长任务归因到某一种输入。
[首尾导航续查](ux-audit-table-page-navigation-2026-10-21.md)增加按任务开始时间分段的
观察，以及末页单元格和 textarea DOM 值观察，不将新旧不同范围的总数直接比较。

这些是开发中的顺序观察，不是随机化配对实验；各试验没有单独持久化完整源码
摘要，因此不能把差值归因给某一个微优化。自适应前已经有延迟解析及增量行写入。
宽表挂载数没有变化，其小幅耗时差异尤其不能宣称为预算改动的收益。
仅延迟解析的较早试验也没有证明稳定提速；相应结果保留，不能挑选漂亮数字替代。
自适应后窄表仍出现 51ms 长任务；显式 GC 后 JS heap 不是 RSS、泄漏证明或服务器
OOM 验收。解析仍在主线程，延迟调度不能中断已经开始的一次解析。
