## 已实现

### 一张表格，而不是预览和网格各一份

- 面板标题只保留“表格工具”，去除旧的规范/创建/增行/增列模式和说明面板。
- 上方就是经过共享 GFM、数学和安全链渲染的实际表格；点击单元格编辑原始内容。
  下方 Markdown 可直接输入，两者双向更新。没有第二份独立网格。
- 表格中的链接只呈现为惰性文本、图片只呈现 alt，不因编辑点击发生导航或远程请求。
  普通 Reader 的原有链接/图片策略不变。
- 四边 `+` 添加顶部/底部数据行、左侧/右侧列；新增列同时更新表头、分隔行和数据行。
  桌面靠近边缘或键盘聚焦时显示，触摸设备常显。视觉圆点 24px，点击区 44×44px，
  避免最初大块按钮遮住移动端内容。
- 继承纸面/石墨灰/海绿色 token、现有字体、细边框与底部主操作；没有新增设计 token。
  用户要的是修复和编辑当前表格，不是电子表格产品，因此未增加工具栏、复杂网格、
  多步向导或另一套渲染器。

### 草稿、焦点与输入保护

- 面板保存打开时的正文、范围和编辑修订。后台正文变化不能重新初始化或覆盖工具
  草稿；应用失效，只能明确“重新预览”。
- 不完整或超限 Markdown 原样保留。最近有效表格仍可读，但单元格和边缘操作停用，
  不会反向覆盖用户尚未写完的 Markdown。
- 单元格组件身份稳定，连续输入不会重挂载并丢失焦点；公式/强调等保持实际渲染。
- Enter 和方向键移动单元格，左右键只在无文本选区且已到文本边缘时跨单元格；
  组合输入、修饰键和 Shift 选区保持原生行为。
- Enter 即使在末尾单元格也不提交消息表单。Escape 先退出单元格，再关闭面板，
  不顺带关闭底层源码预览；Tab 限定在顶层对话框中，关闭恢复逻辑编辑器焦点。
- 应用重新校验源版本、范围和真实 GFM 表格 DOM，以一个 CodeMirror transaction
  修改草稿，单次撤销恢复原文。未绕过原有保存/版本/冲突流程。

### 有界预览和原文保真

- 工具保留 1 MiB UTF-8、5,000 物理行、200 列、50,000 单元格上限；超限拒绝，
  不截断原文。底层创建/增行/增列纯接口仍兼容，不作为面板模式公开。
- 实际预览每页最多 30 条数据行和 1,200 个单元格；宽表动态减少每页行数。
  翻页能够访问后续行，底部追加显示真实末页；Markdown 和最终应用保留完整范围。
- 规范化不吞掉相邻带 `|` 的普通段落，不把引用/列表中的围栏示例自动当正文。
  明确选择的代码示例仍可按选区处理；HTML 合并单元格和不可靠结构拒绝猜测。
- 保留可确认的引用/列表前缀、转义竖线、单元格内容和对齐意图。
  CRLF/LF 混合文档按每条物理换行计算源位置，输出沿用已有文档换行约定。
  行索引只线性扫描，不在每条行记录上重复扫描完整片段。
- 修复普通 Reader 和表格编辑预览丢弃 GFM center/right 样式的问题；这是共享
  表格展示修复，不改变富文本 v5 解析版本或 canonical Markdown。

## 实际失败与修复历史

1. 隔离浏览器 harness 首次编译未包含传递依赖搜索路径；随后因 Windows 解析到
   两份 React，触发 `useMemo` 错误。修复的是 harness 依赖解析并固定 React
   单实例，没有替换业务 React 或放宽断言。最终页面/控制台错误均为零。
2. 首次移动截图发现 44px 不透明边缘按钮过大。改为小圆形标记，保持 44px
   交互区后重新执行浏览器专项，并查看桌面、手机和平板实际截图。
3. 新增混合 CRLF/LF 精确边界用例在修复前 **11 通过 / 1 失败**，实际失败于表格
   模型识别；旧实现假定片段内所有换行等宽。改为每条换行推进真实偏移后，
   该文件 **12/12** 通过。没有把这个失败记成旧测试或删除用例。
4. 前一个全量 service-free 检查点为 67 文件 **1,449/1,449**，发生在新增混合换行
   用例之前；不得用该数字证明新用例通过。最终重跑以证据 JSON 为准。
