# UX quick review — 表格中的字面反引号

2026-10-20；先记录修复前事实，再修改代码。范围限于源码表格工具的识别、
规范化与单格校验，面向整理技术 Markdown 的用户；不改变阅读渲染器或交互布局。

## 范围与证据

- 使用实际安装的 ReactMarkdown/remarkGfm 静态渲染，以及实际 TypeScript
  转换器；数据完全合成。[基线](ux-audit-table-code-span-2026-10-20-evidence/baseline-observations.json)
  绑定修复前源码摘要；[诊断脚本](ux-audit-table-code-span-2026-10-20-evidence/renderer-diagnostic.mjs)
  从仓库根目录运行。
- 不是浏览器、认证 API、服务器资源或全应用验收；没有真实对话、身份或凭据。
  本次不作无障碍、跨浏览器、生产 OOM 或延迟保证。

## 最重要的结论

GFM 允许不成对的反引号作为普通文字。当前工具却把它们当成始终未闭合的代码
片段，因而拒绝已经正常显示的两列表格。选区没有缺失，重新选择不能解决。
不能简单取消代码校验：真正成对的代码片段仍应保护其内部的标签、链接和竖线；
不成对的符号不能把后面的列分隔符吞进同一个单元格。

**位置：** 修复前 `apps/web/features/editing/markdown-table-tools.ts:159–225`，

和 `escaped-backtick-inside` 均渲染为一张表、两个表头和两个数据单元格；
转换器和规范化却全部返回空结果。成对双反引号对照正常通过。
这里没有发现已保存内容损坏；它是工具不可用及反馈误导。
既有三个成对代码/转义用例通过，见
[基线检查](ux-audit-table-code-span-2026-10-20-evidence/baseline-focused.txt)，
其余按名字跳过，不能当成全套通过。

**影响：** 用户不能用网格整理含有未配对反引号的技术说明，也不能自然地逐字
编辑这类内容；反复调整选区并不能恢复操作。可以手改源码，故不定为高严重度。

**建议：** 在现有有界解析中，仅让确实存在等长闭合符的代码片段拥有内部语法。
未配对反引号保持字面文本，未转义的竖线仍按列分隔符处理；保留全部内容、
显式应用及单次撤销。不以移除校验、猜测合并列或引入新 Markdown 渲染器解决。
匹配查询需要避免对每个反引号重新扫描整条长行。

## 优先顺序与保留项

1. 保留失败基线，增加真实 GFM 与共享 Reader/可编辑预览的前后对照。
2. 统一整表、单格和序列化；覆盖转义的开头、代码中的反斜杠及不同长度符号。
3. 验证字面符号后的真实 HTML 结构仍拒绝、普通列边界不被吞并。
4. 实际源码工作区验证编辑、应用及撤销，再跑受影响的本地门禁。

保留现有单一表格工具、四边 `+`、纸面/石墨/海绿色令牌、分页与预览预算。
这不是界面重设计；不添加服务器接口、依赖、缓存或 migration。

## 尚未覆盖

这是单一语法边界的快速复查，不是完整 Markdown 文法证明。混合嵌套链接、
数学宏及多行单元格仍遵守现有保守限制。实际浏览器、超长输入和门禁结果将在
完成后单列，不把基线静态渲染或旧检查点推导为本轮全部通过。

持续优化目标仍活动、无限预算；不推送、不启动 CI、不部署。

## 修复与续验（保留上文修复前记录）

整表和单格继续使用原扫描器，仅在存在等长闭合符时进入代码上下文；管道序列化
使用同一匹配规则。每行/单格按需建立一次线性索引，每个 UTF-16 代码单元一字节，
没有全局缓存。索引覆盖转义吞掉开头一个反引号的后缀情况，而代码里的反斜杠
不能转义闭合符。未配对符号保持字面文字，真实 HTML/不完整公式仍拒绝。

[扩充失败基线](ux-audit-table-code-span-2026-10-20-evidence/baseline-expanded-tests.txt)

输出；[900 组合对照](ux-audit-table-code-span-2026-10-20-evidence/verified-differential.json)
全部接受、输出相等且幂等。原本不规则行中的未转义竖线仍分列，规范化补齐最大
