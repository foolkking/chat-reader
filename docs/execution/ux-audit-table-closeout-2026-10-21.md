# UX quick review — 表格阶段收尾与下一步

2026-10-21。按用户“价值不大尽快收尾，进行下一步”的新指示，停止开放式表格优化。
本次只复核当前源码、既有合成浏览器证据与测试回执，不重跑相同浏览器矩阵，
不访问生产、不搜索网页、不启动 CI、不推送、不部署。

## 范围与证据

- Web 源码编辑器的现有 Table tool；面向需要校对对话 Markdown 的混合熟练度用户。
- 复核[最终检查点](ux-audit-table-delimiter-content-2026-10-21.md)及其
  [证据清单](../evidence/table-tool-delimiter-content-2026-10-21.json)：
  当前 20 个源码/测试 SHA-256、29 个制品的大小与 SHA-256 全部吻合。
- 该检查点通过 122 项专项、69 文件/1,513 项无服务回归、76 个 Chrome 场景，
  以及 lint、非增量 typecheck、单 worker build；这些是既有回执，不是本次重跑。
- 已读[大表输入观察](ux-audit-table-input-layout-2026-10-21.md)和
  [撤回试验](ux-audit-table-raw-input-2026-10-21.md)；不把零次命中的快路径计作收益。
- 未审计：真实账户全应用、Reader/Share/Offline/PWA、物理设备、辅助技术、
  跨浏览器和服务器资源行为；不作完整无障碍或零 OOM 声明。

## 最重要的结论

1. **表格阶段可以收尾。** 用户要求的上下双向编辑、单模式简化、四边 `+`、
   有界分页、无损应用和一次撤销已有实际工作区证据，不需要继续增加功能。
2. **继续修大表性能的边际价值暂不明确。** 极大合成表格仍有长任务，但编辑可完成；
   没有真实使用频率，也没有稳定端到端收益支持增加事件信任、缓存或新渲染路径。
3. **下一步优先处理已有明确证据的稳定性风险。** 发布检查与备份仍用
   `compose run ... api`，可能因默认镜像缺失触发本机构建；这是比表格微调更高价值的工作。

## 发现与取舍

| ID | 类型 / 维度 | 严重度 | 置信度 | 工作量 |
| --- | --- | --- | --- | --- |
| PERF-02 | 极大表格输入长任务 / 感知性能；保留已知问题 | Medium | Observed（此前同机合成 Chrome 测量）；真实频率未知 | M |

**PERF-02：** 既有 10×4,000 / 200×248 合成表格样本出现主线程长任务，
不等于典型表格不可用、INP 指标或服务器 OOM。位置与完整样本保留在上述输入观察。
本轮不再改产品源码；仅在实际资料上出现持续卡顿、无法完成任务或内容安全回归时重开。
新增性能分支必须先证明实际命中及稳定收益，不能用功能绿灯代替。

**OPS-01：** `deploy/preflight_release_space.sh` 的四类存储大小检查和
`deploy/backup.sh` 的大小检查/打包调用服务 one-off；当前生产 Compose 为 API 同时声明
`image` 与 `build`。2026-10-19 的前置检查已实际产生意外 `latest` 镜像，
详见[发布记录](OOM_RELEASE_2026-10-19.md)。使用小内存主机的读者可能因此遭遇
维护引发的资源争用；这不是已证明的每次导入崩溃根因。
建议复用现存 API 容器的不可变镜像和只读卷，拒绝缺失/不完整来源，
通过真实 shell + 合成 Docker 验证无 build/pull/up；不使用服务器不支持的
`compose run --no-build`，也不在生产试跑。

## 下一步与不做的事

1. 收口上述 OPS-01：仅本地改脚本、针对性回归和运维文档；完成后结束这次有界续查。
2. 之后按真实用户故障决定导入/任务恢复的下一轮，不重复实现已经发布的
   TOC 返回、噪声审阅、批注 Context 1.1 或按项目拖放。
3. 大表性能放入条件触发的待办；不继续找格式边角，不换编辑器、不增加模式、
   不恢复已撤回试验。
