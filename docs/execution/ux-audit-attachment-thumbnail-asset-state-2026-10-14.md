# 附件缩略图资产状态隔离审查（2026-10-14）

## 范围与修改前证据

本记录先于本项源码修改建立，范围是统一附件查看器底部缩略图和多图片
总览中的图片加载失败状态。按用户当前要求，本批不启动服务、不登录、
不运行浏览器或自动化验证、不提交 CI、不部署。

修改前文件：

- `apps/web/features/attachments/attachment-viewer.tsx`

源码证据：

- `ViewerThumbnailImage` 用本地 `failed` 状态记录图片加载失败。
- 修改前的清理 effect 依赖 `attachment.id` 和 `source`，没有包含
  `asset_object.sha256`。
- 当同一附件 ID 的资产被替换且继续使用同一内容 URL 时，组件可能被复用；
  新资产会继续显示旧资产留下的失败占位，直到查看器被完全卸载。

这是缩略图局部状态残留，不是服务器内容损坏或新的网络请求问题。主查看区域
和复杂附件子视图的资产身份隔离不受影响。

## 处理决策

让缩略图失败状态与统一查看器使用同一附件资产身份：附件 ID 加资产 SHA-256，
无哈希时回退内容 URL。资产替换时只重置本地失败标记，保持现有按需读取、
懒加载、Blob URL 释放、权限和资源预算不变。

## 本地实现与边界

已让 `ViewerThumbnailImage` 的失败状态清理依赖统一附件资产身份：
附件 ID 加资产 SHA-256，无哈希时回退内容 URL。资产替换时只重置本地失败
标记，不扩大缩略图查询或预加载范围；现有按需读取、懒加载、Blob URL 释放、
权限和资源预算保持不变。

本批不宣称浏览器布局、真实图片加载、CPU/RSS 或运行时验收结果；用户可在后续
自行验证同一附件替换资产后重新打开总览和底部缩略图。
