# 表格字面块上下文与 CRLF 保真 — 2026-10-20

状态：阶段检查点，后续由 [GFM 校验续查](TABLE_TOOL_GFM_CONTEXT_2026-10-20.md)
修复扩充诊断发现的三处差异。持续目标保持活动、无 Token 预算上限。不推送、不启动 CI、
不部署。无新增依赖、API、migration、持久化协议或生产变更。

## 已修复的证据链

实际 `react-markdown` + GFM 的 `skipHtml` 输出显示：紧贴 `<div>`、`<details>`、
`<pre>`、`<script>` 等开始标记，以及 HTML 注释、CDATA、处理指令中的表格文本，
并不是可渲染的 Markdown 表格。旧工具却允许自动打开、编辑和应用，孤立预览
使人误以为规范内部行就能让完整原文显示表格。

- 修复前专项 **72 通过 / 1 失败**；实际工作区浏览器在 28 场景通过后，
  因该 HTML 场景的 Apply 错误可用而失败。
- 使用已有解析树的 `HTMLBlock`、`CommentBlock`、
  `ProcessingInstructionBlock` 作为字面块保护，不引入第二套 HTML 状态扫描。
  原有 fenced/indented code 保护和完整选区授权保留。
- 明确完整选中示例仍可编辑；不删除外层 HTML、注释或代码标记，也不关闭
  Reader 的 `skipHtml`。这是编辑示例内容，不宣称改变其完整原文渲染策略。
- 空行已结束普通 HTML 块、已闭合注释/处理指令、普通行内标签，以及退出引用/
  列表容器后的真实表格仍可自动编辑。不是简单“原文出现 HTML 就禁用”。

接入后出现另一次 **72 通过 / 1 失败**：CRLF 空行被安装的 Lezer 原始字符串
解析当作含 CR 的正文，导致合法表格仍被判为 HTML 块。同类问题还会漏读空行后
的实际链接定义；扩充后的失败基线为 **72 通过 / 3 失败**，不计作通过。

该阶段处理：

1. 独立原始 CRLF 输入的上下文回退，仅把解析视图中行末 CR 换为等长空格，
   而不是删掉 CR。UTF-16 源坐标不变，回退仍只解析前文到表头。
2. 原始 CRLF 树不能覆盖规范化上下文；实际 CodeMirror 的 LF 冻结树仍正常复用，
   不因本轮变化在每个单元格输入时重建全篇 AST。
3. 有界引用采集也用等长解析视图；引用 ID/URL 和输出内容始终从原始源码切片。
   原 1 MiB 源码、256 条/32 KiB 投影边界不变。
4. 模型范围、单元格、CRLF 序列化和最终 Apply 都保留原文，不把解析空格写回。
   Unicode 前文、完整选区、旧/不完整树及正常 HTML 边界都有回归。

## 界面与交互

只更新原有无可用表格时的一句恢复说明，要求完整选中代码或 HTML 示例。
不增加模式、工具栏、常驻解释或新的交互层；原纸面/石墨/海绿色 token、字体、
4px 间距和四边 44px 控件保持不变。

实际工作区验证完整源码预览和工具预览的区别：字面块不再自动给出一个误导的
可应用表格，真实 HTML 边界外的表格在 Apply 后仍真实渲染，Undo 恢复原文。
显式选中注释内示例后可编辑，但其注释仍保留、完整预览仍没有表格。
截图复核了桌面和 375px 中文提示，未增加溢出或遮挡；不是全界面可访问性评分。

## 后续发现：textarea 遗漏及新引入的引用内误拒绝

该阶段未解决的差异：实际 GFM 将 `<textarea>` 的内容一直
保留为字面 HTML，而安装的 CodeMirror 语法在空行后已开始解析普通 Markdown。
因此该处仍可能被工具误认成可自动修复的表格，也可能错误投影内部引用。
不能因为普通 `HTMLBlock` 的保护通过就宣称所有 HTML 上下文已一致。

实际工作区又确认本阶段新引入的反向错误：
`> <div>`、空的引用行 `>` 后面的合法引用内表格，被安装的编辑器错误地留在
HTMLBlock 中，本阶段新增的节点保护因此误拒绝了它。完整原文实际有一张表格，
工具却没有预览且 Apply 禁用。该例不在当时的九种合法边界中，75/49 绿灯范围不足。

独立库/GFM 诊断和实际浏览器探针单列在证据中，不计入 49 个通过场景。
四例探针区分根 textarea、引用 textarea、内部引用漏出和合法引用表格；其中
引用 textarea 原本已禁用。最初错误要求每例都可应用的探针假设失败也保留，
不把测试假设错误记作额外产品缺陷或通过。

后续 GFM 续查保留上述失败，用实际渲染链协调三处差异，并覆盖关闭标签、
容器退出及引用边界；不使用全局标签开关、不改写外层 HTML。持续目标保持活动，
未以较容易通过的普通 HTML 样本缩小最终要求。

大表长任务、极长前文回退成本、真实手机/辅助技术、完整 Reader/Share/Offline/PWA、
认证服务端、Linux PID 1 和 OOM/2 GiB 长时负载仍未在本轮验收。
