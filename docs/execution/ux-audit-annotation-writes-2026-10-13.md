范围是输入保留、重复提交、部分失败和恢复动作，不扩展到服务器新事务、数据迁移或

## 证据与结论

在上一批 806 项本地回归的精确工作树上运行[探针](ux-audit-annotation-writes-2026-10-13-evidence/probe.mjs)，
[结果](ux-audit-annotation-writes-2026-10-13-evidence/probes.json)绑定上一台账和六个源码哈希。
复用已审查的显式 hook／repository／DOM 替身，执行真实编译组件、事件回调和返回
元素树；通过仅增加 export 读取私有 AnnotationList，不替换产品分支。没有运行
浏览器或真实服务器写入；视觉、实际网络调度及故障频率均未知。探针初次因测试
模块默认导入缺少 esModuleInterop 失败，补正编译选项后完整执行通过。

读取恢复已改善，但写入异常仍有独立问题。最优先的是保护评论输入和部分成功的
结果，避免读者在重试时被过期版本挡住。删除批注前先移除笔记引用，会让一次失败的
删除仍改变笔记。重复创建请求缺乏前端互斥，服务器每个无 ID 的创建会分配新 ID。
此外，笔记已保存但本机草稿清理失败时，现有恢复按钮并不执行它声称的清理。
这些发现需要独立的写入状态和就地恢复，不需要增加轮询或成功通知。

## 当前已有效的保护与验证空白

读取归属、关闭面板后的正文高亮、跨筛选有效选择、笔记本机草稿、服务端 revision、
离线 outbox 和草稿 expectedVersion 校验已经存在；继续复用。评论当前有失败提示，
但提示本身不能证明输入保留。批量操作有删除确认，但确认不能替代部分失败恢复。
网络拒绝也不能直接断言服务端未提交；所有“检查结果”入口必须区分当前值和写入回执。

| 写入路径 | 处理中／互斥 | 失败后的内容 | 部分完成 | 恢复 |
| --- | --- | --- | --- | --- |
| 评论 | 文本提示，无同步互斥 | revision 更替可替换输入框 | 不适用 | 再次失焦；没有明确重试按钮 |
| 批量样式／删除 | 缺少统一状态 | 第一项成功后仍显示旧结果 | 无 | 拒绝逸出回调，可能卡在旧 revision |
| 创建书签 | 无同请求互斥 | 输入简单但可能多次受理 | 不适用 | 无未知结果核对 |
| Notebook | 有 busyRef 和本机草稿 | 大部分保留，expectedVersion 防误清 | 清理失败独立于保存成功 | 清理文案与按钮动作不一致 |

实现先保护输入与已确认结果，再补未知结果／部分失败恢复；清理按钮作为可独立验证
的小修一并处理。继续沿用现有界面层级与 token，错误靠近受影响内容，新增按钮采用
44px 操作目标；仅显式操作及异常反馈，不为例行自动保存增加提示。新界面需另行浏览器
验收，不能套用此前发布截图；本地 Web 启动的既有策略拒绝保持原状，不重试或绕过。

## 中间实施检查点（未完成整批）

FORM-ANN-W01 和 STATE-NOTE-W01 已做本地实现，其他三项仍未修完：

- 评论草稿改由当前访问范围的工作区保留；编辑器是受控输入，不以 revision 更换
  DOM key。筛选、同一对话面板关闭／重开及样式 revision 变化仍保留输入。每次
  按键只更新编辑器，工作区只在草稿出现、消失或操作状态变化时重绘。
- 评论失败被接住并保留草稿；失焦不会自动重提失败请求，读取当前评论不写入。
  当前评论不同于草稿基线时需显式比较／确认；等待确认中的新输入会使旧确认失效。
  同一次未返回保存只发一次；返回时保留用户在等待期间继续输入的较新文字。
- 当前评论已与草稿相同时无需重写；这是当前值核对，不声称是原写入的回执。
  确认成功的更新立即发布并淘汰旧读取；旧访问范围的响应不能发布到新对话。
- 本机草稿清理失败有独立重试，仅尝试原 expectedVersion 的删除；不会重写服务器
  笔记、不会把新输入当成旧草稿清理，其他标签版本冲突继续保留其数据。

- STATE-ANN-W02：每个样式写入确认后立即发布当前记录并淘汰旧读取。一次只运行
  一条操作链；部分失败保留计数和当前选择。读取当前批注不发写入，失败仍可再读；
  完成读取后由用户显式应用样式，已经匹配的项目不再提交。浮窗和展开阅读均可恢复。
- DATA-ANN-W03：先逐项删除批注，全部确认后才清理对应笔记引用。失败立即停止，
  不提前清空笔记。核对只读取批注／笔记／冲突；确认不存在的原目标可由用户独立
  清理引用，其余批注留待重新确认删除。清理失败仍有核对入口，不重新删除批注。
  每次清理使用当前笔记版本并检查当前批注状态；这不是跨请求原子事务。读取后的
  “不存在”不会计入原删除请求的确认数。确认删除或核对不存在后清除对应评论草稿，
  避免留下无入口的未保存状态；其他草稿保留。
- STATE-ANN-W04：书签从首次请求就持有固定 UUID；未完成时互斥，响应未知时保留
  原请求。核对按该 ID 检查当前批注，只读成功且找不到时才提供显式原 ID 重试；
  已存在则完成核对而不再创建。当前 API 的重复 ID 冲突和离线 add 的唯一性继续
  生效；不假称创建接口是幂等成功。创建中的进度可见，迟到回复不会重新打开别的对话。
