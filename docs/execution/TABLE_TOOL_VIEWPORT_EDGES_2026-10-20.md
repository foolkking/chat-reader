## 实现与设计约束

- 阅读者需要在刚编辑的宽/长 Markdown 表格旁直接增加整行/整列，不应先找
  全内容中点。沿用既有纸面、石墨、海绿色 token、字体及 4px 间距基准；
  仍只显示标题、实际可编辑表格、Markdown 和取消/应用，不增加说明或工具栏。
- 四个 `+` 使用同一可见预览外框作为定位依据。上下按钮位于固定宽度的行边缘，
  左右按钮位于可见滚动区域的列边缘；表格本体在它们中间独立滚动。
- 每边预留 44px 点击区域，24px 小圆标记保持原样，不遮挡单元格、输入框或
  滚动条。桌面 hover/focus 显示、触摸常显、禁用和无障碍名称沿用原行为。
- 使用 CSS 正常布局/局部定位，而不是新增滚动监听、ResizeObserver、定时器、
  宽度状态或第二张表格。拒绝新增模式按钮，也不以表格全宽/高计算按钮中心。
- `gridRef` 仍包住四个按钮和真实表格，新增后的延迟焦点不被误判为“用户已离开”。
  之后主动移向 Markdown 或其他控制的焦点仍优先，旧定位不能抢回来。
- 增行作用于完整草稿首尾，增列同时更新所有行，不是只编辑当前预览页。
  30 行/400 单元格挂载预算、大小限制、原文偏移、源码 stale 保护、一次撤销
  及显式保存行为不变。
- 短横屏仍可正常纵向滚动弹层工作区；不承诺所有内容同时可见，也不把按钮
  放到固定头部/底部遮挡层上。新的两轴定位不依赖滚动事件或 viewport 尺寸采样。

新增的四个场景，以及原场景的焦点/待渲染保护，共同覆盖：

- 200 列水平开头、中间、末尾，上下按钮完整位于可见窗口内；
- 12 列、30 行的两轴滚动，四个按钮的中心 hit-test 都命中真实按钮；
- 375px 触摸的宽表增行及长表增列，667×375 横屏的工作区纵向滚动；
- 直接鼠标坐标/触摸坐标执行，不使用会自动滚入元素的 locator 点击掩盖缺陷；
- 每个区域至少 44px，按钮不进入单元格/滚动条 viewport；
- 从末页追加/前端插入仍保留全部原始行列，定位新单元格；Enter 不提交表单；
- 旧预览、无效输入、源码冲突、一次 Undo 和客户端保存 payload 的既有行为。

桌面亮色、手机深色和短横屏截图已做局部视觉检查：按钮没有盖住表格或页脚，
未出现页面横向溢出，仍为同一张真实渲染表格和一个 Markdown 编辑器。
这不是新的全界面可访问性评分；既有字体、颜色和组件 token 未在本轮重设计，
未做辅助技术、真实手机键盘或触控硬件验收。
