## 已实施源码

### NAV-REPLAY：显式重复激活不依赖 URL 变化

- `search-result-target.ts` 比较会话、消息版本、块、范围和面板目标身份，忽略参数
  顺序及纯展示设置；有精确实体时面板开关也不改变目标，只有旧的无实体面板链接
  仍按开关区分文件／批注。LibraryShell 只在目标与当前 URL 等价时递增内存激活序号；
  不同目标沿用正常 URL 导航，不向书签加入 nonce。
- Reader 将此序号接入既有导航键及文件／批注面板开启流程。保留原 Reader key、
  导航所有权、canonical 范围校验、真实 DOM 锚点和程序滚动保护，不以强制重挂载
  代替再次定位。直接书签恢复仍走普通初始导航。
- 文件面板重复激活清除隐藏目标的筛选，按新激活重新聚焦已提交的真实行；
  不自动打开预览或下载。批注面板清除可见性筛选、等待目标数据与 DOM，展开单条
  回顾时只为本次激活对齐目标序号，不重置阅读模式、评论草稿或后续手动回顾。

### OFFLINE-DUPLICATE：本地实体与 tombstone 为索引投影权威

新增只读 `offline-search-documents.ts` 投影。以会话和批注实体 ID 合并持久文档与
本地批注：本地当前文本、版本和保存锚点优先，软删除记录压住旧搜索文档。
没有对应本地实体的旧文档继续保留；可识别身份的旧重复记录仅保留一份，同文但不同
实体不合并。缺 metadata 时只识别已有 `local-annotation:`／`annotation:` 前缀；
无法推断身份的 opaque 旧记录不猜测删除，也不宣称其重复一定可消除。
正文、文件、description 和 notebook 的既有投影域不变。

没有改写包、删除 IndexedDB 记录或升级 Dexie；去重只发生在内存索引输入边界。

### OFFLINE-FRESHNESS：内容订阅与有代际的重建

- LibraryShell 用现有 Dexie `liveQuery` 事务订阅 `searchDocuments`、`annotations`、
  `notebooks` 三个内容 store，不订阅 outbox 或阅读位置。内容通知先隐藏旧结果、
  退休旧选择，再以 80ms 短合并调度重建；不为每次编辑扫描全部 message。
- worker 初始化串行化，重建和查询均校验当前代际；旧快照定时器不能覆盖显式新读取，
  较早初始化不能发布新索引的 ready 状态，旧查询不能重新展示陈旧命中。
- 捕获离线访问代际和当前数据库句柄，在异步边界重新检查。账号代际变化或卸载退休
  待执行工作；不在“新身份尚未安装”的事件内自行重新授权。订阅捕获／读取失败显示
  原有搜索不可用状态，显式重试可重新订阅；队列失败不阻塞后续重建。
- 保留本地对话读取成功先于可选搜索初始化的顺序、失败反馈及已有副本。

这仍是完整语料重建，不是增量索引或大库性能优化。80ms 是合并窗口，不是已测得
的端到端延迟保证。当前对话缓存查询等其他界面不在本批治理范围。
