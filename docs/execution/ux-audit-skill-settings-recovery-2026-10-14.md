范围是 `apps/web/components/skill-settings.tsx`。证据来自当前工作树源码及 API
错误类型／后端路由静态检查；没有观察真实请求或渲染结果。

源码审查确认：

- 列表读取错误有重试，但文本未按 HTTP 状态翻译。
- 上传失败、首选切换、启用状态、删除和重命名失败直接展示底层异常消息。
- 写入 mutation 的 `onSuccess` 中先清空上传文件／显示成功或已更新服务器状态，
  然后等待 `refreshSkills()`；如果刷新失败，Mutation 最终会进入 error，界面
  将成功写入误呈现为失败，甚至已清空用户刚选的文件。
- 旧分类的延迟读取／Mutation 回调是否会影响切换后的分类，需要守卫；本批先
  按当前组件没有挂载／分类代次保护这一代码事实界定修复，不推断实际发生频率。

## 发现与优先级

| ID | 类型／维度 | 严重度／置信度 | 位置与证据 | 用户影响与建议 | 工作量 |
|---|---|---|---|---|---|
| SKILL-STATE-01 | Defect；状态／结果一致性 | High；Observed (code)，渲染 Inferred | `SkillSettings` 的上传 `onSuccess` 清文件并提示成功后返回 `refreshSkills()`；刷新拒绝会把 mutation 转成失败 | 用户可能重传已成功的文件或以为操作被撤销。分离写入确认与列表刷新，保留成功结果并提供只读重读。 |
| SKILL-ERR-02 | Defect；错误反馈与恢复 | Medium；Observed (code)，渲染 Inferred | 上传和四类 mutation 的 error 分支直接呈现 `.message` | 服务端／网络文本不稳定且可能是英文技术信息。映射稳定的双语提示，并让未知写入结果提示先重读再决定是否重试。 |
| SKILL-STATE-03 | Opportunity；异步状态归属 | Medium；Observed (code)，运行时影响 Inferred | 查询按 `category`、`locale` 变化；mutation 成功后统一刷新 Skill 与 resolved-skill 缓存，但组件没有显式的请求分类代次／退休回调守卫 | 快速切换设置分类时，晚到请求的缓存与反馈边界不清。仅在仍挂载且所属分类／语言未变时发布局部成功反馈；有效服务器写入仍须刷新其真实全局数据，不虚称取消。 |

## 保留边界

- 不实现 Skill 查看／编辑／历史 UI，不添加语义候选、采用或校验流程。
- 不改变 Skill 文件、bundle 版本、首选、语言、权限、上传或删除 API 语义。
- 不自动重试／重传；用户文件在错误和结果未知时保留。
- 后台刷新只读，不新增轮询、网络频率或依赖。

## 实施记录

`apps/web/components/skill-settings.tsx` 现在将用户 Skill 上传、首选切换、启用／
禁用、重命名和删除的异常映射为稳定的中英文恢复文案；已知会话、权限、资源
不存在、并发变化、输入限制和限流状态分别给出下一步，未知写入结果提示先重载
列表核对，不直接呈现底层异常。

写入成功与后续列表刷新已拆开处理。创建成功后仍保留成功结果和清理已确认的
上传选择；刷新失败只显示“操作已完成但列表未刷新”，并保留列表重试入口，
不把成功写入误报为失败。组件卸载和分类／语言作用域变化时，成功反馈只发布
到仍属于当前面板的作用域；已确认的服务器写入仍不被 UI 假称取消。
