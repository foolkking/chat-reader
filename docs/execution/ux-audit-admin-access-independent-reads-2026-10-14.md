# UX 审查与修复前证据：管理员访问设置独立读取

日期：2026-10-14

## 范围与证据

本次审查覆盖设置中的管理员“用户与访问”面板初始读取。证据来自当前源码；
没有启动服务、登录、浏览器、测试或构建，因此没有运行时截图或网络时序证据。

已查看：

- `apps/web/components/admin-access-panel.tsx`
- `apps/web/lib/account-access-client.ts`

## 发现

### ERR-ADMIN-ACCESS-02 · 四个独立读取被单个 Promise.all 绑定

| | |
|---|---|
| **Dimension** | Error recovery / Resilience |
| **Severity** | Medium |
| **Confidence** | Observed (code); rendered consequence Inferred |
| **Effort** | S |
| **Location** | `apps/web/components/admin-access-panel.tsx:57–64` |

**Evidence.** `load` 同时读取访问概览、用户列表、邀请列表和当前账户；
任意一个 Promise reject 都会进入统一 `catch`，成功返回的其它结果不会写入
状态。面板随后只能显示统一错误和空的其它视图。

**Why it matters.** 例如账户资料读取暂时失败时，管理员本来仍可查看用户和
邀请；一个短暂的单资源故障会抹掉整个首屏的可用信息，也不告诉用户哪些区块
实际失败。

**Recommendation.** 对四个读取使用 settled 结果：成功资源照常提交，失败资源
保留上一份已显示数据，并显示稳定的部分加载恢复提示和现有刷新入口。不要引入
额外轮询、请求或写入。

## 修复契约

- 只改变初始读取的结果合并和提示，不改变 API、权限、写入、确认或一次性链接。
- 成功资源必须仍然更新；失败资源不能用空数组覆盖已有状态。
- 失败继续使用既有稳定错误分类，不展示服务端 detail。
- 本批不增加请求次数、自动重试、缓存格式或部署变化。

本报告在源码编辑前写入，后续只做上述范围内的本地修复。

## 已实施的源码修复

`AdminAccessPanel` 现在使用 settled 结果分别提交访问概览、用户、邀请和当前
账户读取。成功的资源照常更新；失败资源保留已有数据并显示稳定的部分读取提示。
首次读取账户身份失败时隐藏重置／启用／禁用等用户写操作，避免在当前账户身份
未知时误操作；概览或列表失败时相应区块不会把空数组误报为真实的空状态。

本批仅做源码与文档修复，未启动服务、登录、运行测试／构建／静态验证，未提交、
未触发 CI，也未部署；运行时效果由用户后续验证。
