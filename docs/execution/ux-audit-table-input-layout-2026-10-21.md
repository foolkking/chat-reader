# UX quick review — 大表输入布局成本

2026-10-21；先交付观察与验证计划，再进行性能采样及修改。

## 范围与证据

仅检查源码表格工具的大表输入响应，不扩展为服务器/OOM、全应用或完整无障碍
审查。用户是整理长技术 Markdown 的混合熟练度读者；目标仍是可编辑表格与
Markdown 双向即时反馈，而不是通过隐藏源码、截断原文或放弃保护来提速。
现有证据为 Windows、Chrome 155.0.8059.82、1440px、未节流 headless、真实工作区
上的合成表格观察，以及当前实现源码。API 与动态加载等保留测试适配器。

[上一轮分段 profile](ux-audit-table-input-layout-2026-10-21-evidence/prior-source-bound-performance.json)
的 [20 项源绑定](ux-audit-table-input-layout-2026-10-21-evidence/baseline-source-sha256.json)
已逐项核对，当前源码一致。以下不是物理显示器绘制、INP、真实用户频率或移动
设备性能测量。没有生产数据、凭据、联网搜索或未经授权的发布操作。

## 关键发现

| ID | 类型/维度 | 严重度 | 置信度 | 估算 |
| --- | --- | --- | --- | --- |
| PERF-01 | 大表输入响应的优化机会 | Medium | Observed（source-bound Chrome measurements）；具体瓶颈未确定 | M |

**位置：** `markdown-table-dialog.tsx` 的网格更新、受控 Markdown textarea 与共享
预览渲染；后续采样需要区分 JS、样式、布局和浏览器原生输入工作。

**证据：** 10×4,000 合成表格的首行网格→Markdown 更新帧中位数 61.9ms，末行
62.8ms；相应段仍记录 51ms 和 54ms 主线程长任务。200×248 宽表更新帧分别
47.2/55.6ms。它们只是各五次输入，不是硬件无关 SLA，也没有证明唯一热点。

**影响：** 大表校对时，持续输入需要等待较大的工作片段；有界可视化并未保证
全部输入成本都与可视单元格数相同。不声称用户无法完成编辑或已经观察到流失。

**建议与顺序：**

1. 对大窄表实际采样浏览器 Script/Layout/Style 计时及轨迹，避免只看 JS CPU 栈。
2. 保持同一数据、输入位置与产品源码绑定，尝试最小的局部修正；没有明确证据
   就不引入 Worker、新编辑器架构或全局缓存。
3. 修正前后继续验证源文本、光标、选区、IME、预览保护、Apply/Undo 与窄屏。
4. 除局部性能观察外，最终再运行受影响的完整本地门禁，不把时序保护换成速度。

## 保留项与尚未证实的假设

保留单模式、四边 `+`、首尾/逐页导航、120/400 挂载预算、完整可编辑 Markdown、
1 MiB/50,000 单元格限制和一次 Undo。原生 textarea 整值写入及长行软换行可能
产生浏览器布局成本，但此时只是待验证假设，不能从长任务时长直接得出。
真实移动设备、辅助技术、跨浏览器、长期内存及服务端行为未在本次范围验收。

目标仍活动；仅本地，不推送、不启动 CI、不部署。

## 本轮实现与未保留的试验

继续采用既有 Web 工作台，不改布局、字体、色值、44px 操作区或四边 `+`。
用户仍在上方真实渲染表格与下方 Markdown 之间校对，改动只进入未保存草稿。

保留的局部改进：

1. 规范草稿缓存当前物理行起点，网格修改只序列化该行并更新行/UTF-8 差值；
   原始 Markdown 和结构变化使索引失效，没有进程级或历史草稿缓存。
2. 普通单行 Markdown 编辑可复用已经解析的表格；列数、换行或标记不确定、
   输入超限时回到原有完整解析。该路径仍扫描/复制完整字符串，不是 O(1)。
3. 单元格保留最后接受的本地输入值，超限操作不截断原文；Markdown 仍由
   React state 控制，不保留独立的 DOM 草稿或动画帧写入队列。
4. 首列向左和末列向右无目标时不退出输入；连续输入粗体/链接等内容不丢焦点，
   Escape 回到当前单元格。旧预览、未解析草稿和失效源范围仍不能应用。
5. 修复单元格首尾 NBSP、BOM、em/narrow 空格被 `.trim()` 当作边界删除的问题。
   只去掉普通空格/Tab，缺外侧竖线的表格也保留这些内容；最终规范化幂等。

曾试验直接构造普通文本表格来绕过共享解析。样本中网格输入的共享解析次数
从五次变成零次，但 10×4,000 输入仍约 60ms，200×248 仍约 47–50ms，没有
稳定的输入延迟收益。该分支已经撤掉：**所有可视预览继续经过现有 GFM/Math/
sanitization 链，再验证真实表格形状**。源码草稿的保守解析快路径不是展示渲染器。
先前 DOM 单独写入、帧合并等试验也未保留；这些顺序试验不能隔离因果。

## 本轮发现与失败边界

| 项目 | 实际观察 | 最终处理 |
| --- | --- | --- |
| Unicode 内容丢失 | 规范化输出删除 NBSP/BOM 等；实验预览与实际 GFM 内容不同 | ASCII 边界线性扫描，保留 Unicode 内容；撤掉另造表格的展示分支 |
| 修复中引入的性能回归 | suffix 正则在既有 150,000 空格/25,000 重复角括号用例触发 10 秒 watchdog | 改为头尾索引线性扫描，不提高 watchdog、不跳过用例 |
| CRLF 集成 fixture 假设错误 | 新测试在工具打开前即失败，真实 CodeMirror 文档已经规范为 LF | 集成测试使用真实 LF 文档并粘贴 CRLF；既有独立弹层/转换器另测 CRLF 保留 |
| 大表输入长任务 | 去掉可视解析次数仍没有稳定降低下一帧观察 | 不宣称修复；保留原性能问题与后续采样方向 |

失败摘录是诊断证据，不冒充拥有完整源码绑定的早期验收；最终门禁单独绑定
当前 20 个源码/测试摘要。全部为合成资料，未运行服务器、数据库或生产压力负载。

[证据清单](../evidence/table-tool-input-layout-2026-10-21.json)记录 24 份相邻制品、
六项命令回执和门禁前后相同的 20 个源码/测试 SHA-256。全程不推送、不启动 CI、
不部署，没有新 migration；无限预算目标仍活动。

| 本地门禁 | 实际结果 |
| --- | --- |
| 五文件表格/引用/共享渲染/焦点专项 | 117 通过，0 失败/跳过 |
| 全部 69 个无服务 UX Node 文件 | 1,508 通过，0 失败/跳过；包含上面的 117 项 |
| 实际工作区 Chrome 场景 | 72 通过 |
| Web lint / 非增量 typecheck | 退出码均为 0 |
| 单 worker Web build | 退出码 0；明确 `NEXT_BUILD_CPUS=1`、非 standalone |

新增桌面场景检查连续输入富标记、反复 Unicode 网格/Markdown 编辑、CRLF 粘贴、
Unicode 边界值的 Apply/单次 Undo，以及左右末端不退出输入。原有 320/375px
触摸、输入法 CDP、待解析/待预览保护、首尾分页、代码/公式/引用和失效源码
场景全部保留。桌面弹层及 375px 暗色触摸截图已查看，没有新增模式、说明、
遮挡或页面横向溢出；这不是完整无障碍分数或真机验收。

最终 profile 仍是每位置五次合成、未节流输入：

| 表格 | 首行输入/下一帧中位数 | 末行输入/下一帧中位数 | 原始 Markdown 值/下一帧中位数 |
| --- | ---: | ---: | ---: |
| 10×4,000 | 61.6ms | 62.5ms | 18.1ms |
| 200×248 | 47.7ms | 51.8ms | 23.9ms |

大窄表仍有 63ms 网格、52/63ms 末行主线程长任务。普通预览的共享解析次数
恢复为五次输入/五次解析；显示省略号的超长单元格仍可复用不变的预览。
不把一次波动或减少解析次数当作延迟收益，也不把 JavaScript heap 数值当作 RSS。
原生 textarea 整值写入/软换行仍是后续可检验假设，不是已确定的唯一瓶颈。

API、Next 加载、assistant-ui 源转发及无关富视图仍有明确测试适配器；未执行
认证服务器、完整 Reader/Share/Offline/PWA、真实候选窗口、其他浏览器、
物理设备、长时间内存或服务器 OOM 验收。早期失败与顺序试验保持原边界，
没有因为这次绿灯而改称通过。
