# 项目管理操作错误文案审查（2026-10-14）

## 范围与证据

本轮只审查普通用户在项目侧栏和项目设置中创建项目、保存项目设置、
拖动移动对话或调整项目顺序时的失败文案。证据来自当前源码；没有启动本地
服务、登录、浏览器或线上页面，因此没有对实际布局、焦点或运行时频率作断言。

## Findings

### PROJ-ERR-01 — Medium / Observed (code)

项目设置保存失败时，`project-settings-dialog.tsx` 直接渲染
`mutation.error.message`。API 的 4xx 可能是服务端业务文案，网络或代理失败则
可能是实现错误文本；保存失败虽然保留草稿，但错误区域不能稳定说明是权限、
名称冲突、项目变化还是暂时不可用。

### PROJ-ERR-02 — Medium / Observed (code)

侧栏创建项目失败时，`project-sidebar.tsx` 将 `createMutation.error.message`
原样传给创建表单。重复项目名称等可识别业务失败与未知连接失败没有稳定区分，
中文界面也可能出现英文或底层请求文本。

### PROJ-ERR-03 — Medium / Observed (code)

拖动对话移动和项目排序失败时，侧栏回滚本地快照后仍有路径直接显示异常原文：
对话移动只特殊处理 revision conflict，其他错误拼接 `error.message`；项目排序
则完整展示 `Error.message`。用户看到的恢复信息因接口和失败类型而变化，无法判断
是应刷新、重新核对归属，还是稍后重试。

## 为什么影响用户

项目侧栏是普通用户整理会话的高频入口。错误发生后本地快照会回滚或草稿会保留，
但原始异常文本会把用户带入实现细节，尤其在名称冲突、权限变化和网络短暂失败
之间难以做出正确下一步判断。这是可完成但容易误操作或重复提交的核心组织路径
反馈缺陷，定为 Medium。

## 处理决策

- 新增项目操作错误文案边界，按创建、保存、移动、排序和 HTTP 状态分类显示稳定
  的中英文提示。
- 保留名称冲突、权限不可用、资源不存在、并发变化和暂时性失败的恢复方向；
  未改变写入请求、乐观更新、快照回滚、草稿、重试或缓存刷新逻辑。
- 仅允许原始错误参与本地分类判断，不再直接渲染给用户。

## 本地实现

新增 `features/projects/project-error-copy.ts` 作为项目操作共享的显示边界：
名称冲突、权限/不存在、并发变化、参数拒绝和未知暂时性失败分别给出稳定的
中英文提示。项目设置保存、侧栏创建、对话移动和项目排序均改为调用该边界；
原始异常仍只用于分类，写入与回滚流程保持不变。

## 验证边界

按用户当前要求，本批不启动服务、不登录、不运行浏览器、lint、typecheck、build、
测试、CI 或部署；后续由用户自行验证。
