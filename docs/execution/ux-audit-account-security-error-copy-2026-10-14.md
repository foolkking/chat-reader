# 账户安全操作错误反馈审计 — 2026-10-14

这是持续普通用户体验优化中的下一批本地源码修复。本批不启动本地服务，
不登录、不做浏览器或自动化验证，不提交 CI，不部署；用户将自行验证。

## 范围与修改前证据

范围是「账户与安全」中的当前设备退出、存储不可用时退出，以及修改密码并
退出所有设备。当前源码文件：

`apps/web/components/account-security-panel.tsx`

修改前 SHA-256：

`65C3F791054E71B1D227DB822B95BFB406EEF3043C5839EDFDD9F761A31B4A9E`

认证客户端的 `AuthRequestError` 已携带 HTTP 状态码。当前 API 合同中：

- `POST /api/auth/logout` 成功后撤销当前会话并清 Cookie；客户端还要完成本机
  受保护资料清理。
- `POST /api/auth/password` 的 `401` 表示认证或当前密码不通过，`422` 表示
  新密码校验失败；成功会使所有会话失效并清除当前 Cookie。
- 本机待同步状态、偏好持久化和本机清理可能在服务器请求前或之后失败，不能
  把这类未知结果当作“服务器一定失败”。

## 发现

| ID | 类型／严重度／证据 | 当前行为与影响 | 处理决定 |
|---|---|---|---|
| ACCOUNT-ERR-01 | Defect / Medium / Observed(code) | 当前设备退出和“存储不可用时退出”直接渲染 `cause.message`。IndexedDB、偏好保存、网络或清理错误会把英文实现细节、浏览器错误或内部状态暴露在界面上；用户无法判断是本机资料未读出、请求未确认，还是退出已完成但清理未完成。 | 按本机准备失败、服务器响应状态和未知结果分类；只显示稳定的双语恢复文案，保留存储不可用的显式退出入口。 |
| ACCOUNT-ERR-02 | Defect / High / Observed(code) | 修改密码并退出所有设备同样直接渲染 `cause.message`。密码接口成功后还要清理本机状态，响应丢失或本地清理失败时，用户重复提交旧密码可能造成二次误判。 | `401`、`422`、`429` 使用可行动的稳定文案；非明确拒绝的错误说明“结果未确认”，提醒先用新密码尝试登录，避免盲目重复提交；输入继续保留。 |

## 实现边界

- 不改变认证接口、状态码、密码策略、Cookie、离线资料清理、待同步修改
  审查或导航行为。
- 不显示服务端原始 `detail`、浏览器异常文本或内部错误名。
- 不把未知结果标为成功，也不自动重试退出或改密。
- 只修改当前账户安全组件的错误映射和显示文案；原有 `PendingChangesPanel`
  的同步、导出、放弃和重新核对流程保持不变。
- 本批不新增数据库、迁移、依赖或测试预算。

## 实施记录

账户安全组件现在先分别处理偏好保存、本机待同步状态读取和认证操作，因此
本机准备失败不再被误报成服务器退出失败；不可读取本机状态时保留原有显式
“放弃本机修改并退出”确认入口。退出／改密只依据认证状态码与已知本机并发
错误选择稳定中英文文案，不显示原始异常；未知密码结果提示先用新密码在新
标签页检查，避免盲目重复提交。密码草稿、待处理变更审查和成功后的清理导航
未有意改变。
