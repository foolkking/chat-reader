## 关键边界

### 分页与排序

缓存继续使用现有 key：`project-conversations + projectId + sort + direction`、
`conversations + history + sort + direction`，数据改为
`InfiniteData<{items, offset, hasMore}>`。主列表与侧栏使用同一页大小和形状；
位置发布、侧栏乐观移动／失败回滚、删除进度及元数据更新都兼容分页。
未读到末页时不绘制整个范围的“尾部”插入槽，也不乐观追加为全局末尾。
主列表全选只选已加载项并明确说明；项目服务器总数与已加载数不混淆。

保留已有全局列表排序保护。项目手动顺序固定为服务端 canonical 顺序，
不改变共享排序偏好值；别的排序仍有升降序，全局 custom 仍保留原方向。
没有虚拟列表、无测量查询重写或分页性能承诺。offset 分页也不提供跨请求
数据库快照保证；并发修改范围后应刷新，去重不能证明没有跳项。

### 批量操作与恢复

4xx（408 除外）归明确拒绝；网络、超时、408、5xx 及无法分类异常均保守归未确认。
进度的五类总和保持为本次冻结范围。停止不取消服务器已接收的操作，也不回滚已完成项。
仅已确认完成的归档／恢复 ID 进入既有 Undo；核对只 GET 当前状态。
显示“当前已归档”不等于证明原批次写入成功，继续操作仍需用户明确确认。

只读结果面板属于挂载的列表／项目范围，在内存中保留，不是持久化任务平台。
退出、切项目／模式、账号变化会退休旧工作并停止后续派发；迟到工作不能更新新范围。
权限失败时隐藏该恢复表面。刷新／卸载／跨标签页不承诺保留首次批次结果。
批量导出继续使用原任务身份与账号代际隔离；超量拦截不创建任务或替换待重试键。

### 拆分回执与迁移

`POST /api/conversations/{id}/split-workspace` 新增可选 `Idempotency-Key`
（1–128 字符）；无键旧调用仍可执行，但不获得防重复保证。
请求经 Pydantic 规范化后 SHA-256 摘要，包含范围、标题、目标项目等全部字段。
PostgreSQL 按来源 ID／键获取事务 advisory lock；等待后重新查来源权限，
再读取回执。复制结果与回执在同一事务提交，失败一起回滚。

`conversation_split_receipts` 的主键是来源 ID／键；只存摘要及原结果的
一或两个对话摘要，不保存原请求正文或消息内容。只有仍有来源访问权的调用可读回执。
来源硬删除时级联删除；不按 TTL 或数量淘汰仍可重放的键，避免旧键再次创建副本。
这是随显式拆分次数增长的操作账本，**不是已测量的容量上限或自动保留策略**。
原始 PostgreSQL 备份包含该表；可移植 `.cr` 不携带运行期重试账本，格式不变。

前端保存待确认的精确输入、预览与键；同一 Reader 挂载期关闭重开仍能安全重试。
它不是刷新／重新打开标签后的持久化客户端恢复。明确完成后关闭再开始才创建新键。
服务端回执不因目标后来被删除而重建目标；返回的是原结果，不是当前状态保证。
不同载荷冲突不改旧回执，来源无权限仍拒绝。
