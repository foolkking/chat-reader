# 扩展优化方向审查 — 2026-10-28

## 1. 范围与证据

本轮按用户“继续找优化方向，多找一点”的要求，扩展审查当前工作树中的分享、
批注评论、当前对话检索、章节目录、离线附件、批量上传、大列表及复杂附件预览。
面向个人资料阅读与管理的混合熟练度用户，重点看内容能否找全、输入能否恢复、
分享权限是否符合明确选择；不做视觉重设计或全产品 UX 评分。

证据为 `ac9ed3a` 基线上的当前未提交源码、相关合同和历史审查，行号绑定本次
检查点，不是部署版本的运行证据。**Observed (code)** 表示源码事实；
**Inferred** 表示由调用链推断的用户后果；**Hypothesis** 表示尚需测量的问题。
没有访问生产正文或账户资料，没有 web search，没有运行本地测试、lint、
typecheck、构建、浏览器、服务或 migration，没有触发 CI、提交、推送或部署。
本轮只新增报告与导航，不改变产品实现，也不覆盖原有未提交改动。

**NOT SEEN：** 真实发生频率、生产数据规模、浏览器焦点与触控表现、物理剪贴板、
多标签运行时调度、真实 PostgreSQL 性能、屏幕阅读器和视觉对比度。
因此不作性能提升数字、无障碍合规、生产事故或完整安全审计结论。
当前三批搜索源码仍未验收；生产及回退状态以根目录 `PROJECT_STATE.md` 为准。

## 2. 结论

更值得投入的主线是“完整性与恢复能力”，不是再增加一轮宽泛的匹配算法或组件重构。
分享自定义到期时间留空被映射成永久，是本轮最明确、且修复范围较小的风险。
评论已有同一工作区内的草稿保护，但跨对话／路由恢复仍是明确保留的功能边界，
可以作为输入安全增强，不能误报为此前修复失效。
上一批离线索引重建不等于当前对话查询缓存同步失效，这两层应单独核对。
目录、当前对话检索、离线附件引用及大列表存在不同的首批限制，适合分别补上
有界继续访问和真实数量语义，而不是统一提高常数。
复杂附件预览应保留资源预算，增强截断说明，不扩成完整 Office 编辑／渲染工程。
本报告保留 12 个有边界的方向，其中检索分页和数据库性能是既有暂缓项，
不是新发现，也不恢复此前已精简掉的开放式优化清单。

## 3. 可独立取走的小修

1. **TRUST-EXPIRY：** 自定义分享时间必须非空、有效且在未来；只有显式选择
   “永久”才生成 `null`。工作量 S，优先级最高。
2. **STATE-COPY：** 分享面板复用现有复制反馈／手动复制兜底，不再无反馈地调用
   Clipboard API。工作量 S，可与到期校验同属分享小批，但分别验收。
3. **DATA-DOCS：** 修正两份当前系统文档中的账号及附件能力矛盾。工作量 S，
   属知识一致性，不冒充用户功能提升。

工作量为源码层面的粗估：S 小范围修改，M 单屏／局部链路，L 涉及查询合同或结构。
不含尚未执行的运行验证，也不是交付时间承诺。

### 分享信任与表单输入

#### TRUST-EXPIRY · 自定义时间留空会生成永久分享

- **维度／类型：** 信任与隐私、表单防错；Defect。
- **严重度／置信度／工作量：** High；Observed (code)，用户实际触发 Inferred；S。
- **位置／证据：** `apps/web/features/sharing/share-panel.tsx:54–88` 提交前只校验
  密码，`:124–131` 的自定义 `datetime-local` 没有必填约束；`:494–498` 的
  `expiryValue` 将空自定义值与显式永久都返回为 `null`。
  `apps/api/app/services/sharing/share_service.py:674–678` 仅校验非空到期时间，
  所以服务端不会拒绝这个本来合法的永久值。该面板由 Reader 实际使用，不是死代码。
- **用户后果：** 用户选择自定义期限却漏填日期时，链接可能比其意图存活更久。
  这是可撤销分享的配置风险，不代表已经发生生产泄露。
- **建议：** 前端区分“永久”“有效未来时间”“无效／未填”，后者不发创建请求，
  在字段旁显示错误并可返回该字段。复用相同日期解析语义核对编辑入口；
  保留 API 对历史 `null` 永久值的兼容，不靠服务端全面禁用永久来补救。
- **验收：** 自定义空值、无效值和过去时间不发送 POST；合法未来时间生成预期
  时间点；仅显式永久生成 `null`；7／30 天预设、原 Share URL 和旧链接编辑不回归。

#### FORM-COMMENT-DRAFT · 将评论草稿保护扩展到跨对话／路由

- **维度／类型：** 输入与错误恢复；Opportunity，已知功能边界增强。
- **严重度／置信度／工作量：** High（未保存文字的恢复价值）；Observed (code)，
  具体丢稿后果 Inferred；M。
- **位置／证据：** `apps/web/features/annotations/annotation-workspace.tsx:93–98`
  将评论草稿保存在 `scopeKey` 范围内存中；`:143–149` 只有 `beforeunload` 提醒，
  `:170–198` 保存失败仍保留内存草稿。`use-annotation-workspace-reads.ts:74–85`
  在对话／仓储访问范围变化时更换 scope。
  [既有记录](ux-audit-annotation-writes-2026-10-13.md)已明确：同一对话筛选、
  关闭／重开面板和样式 revision 变化保留输入，**不承诺跨路由持久恢复**。
- **用户后果：** 保存失败或仍有草稿时进入另一个对话，SPA 导航不等于页面
  `beforeunload`，返回后没有持久评论草稿可恢复。不能把“关闭同一面板”也算作丢稿；
  那条路径已有保护。
- **建议：** 借用 `apps/web/lib/notebook-drafts.ts:9–45` 的账号访问隔离、
  标签页身份和 `expectedVersion` 模式，为评论增加有版本的本机草稿；
  优先沿用现有 settings 存储，不先升级 Dexie。保存回执只能清理它对应的草稿版本，
  不自动重放失败写入，也不越过评论冲突确认。持久化失败时诚实提示并保留离开保护。
- **验收：** 保存失败后 A→B→A、刷新及重新打开均可找回对应草稿；其他账户或
  已锁定访问范围不可读取；迟到保存不能清除新输入；批注已删除／基线已更新时
  有恢复或比较路径；同一面板保留输入的已有行为继续成立。

### 查询新鲜度与操作反馈

#### STATE-SEARCH-CACHE · 索引更新后，当前对话查询缓存仍可能保留旧命中

- **维度／类型：** 系统状态与内容一致性；Defect 候选。
- **严重度／置信度／工作量：** Medium；Observed (code)，实际刷新时序 Inferred；M。
- **位置／证据：** `apps/web/features/search/conversation-search-panel.tsx:110–131`
  的查询 key 包含来源、对话、文本和筛选，没有内容代际，也未订阅索引更新。
  `apps/web/features/offline/library-shell.tsx:143–246` 的新实现会重建 worker 并递增
  `searchIndexRevision`，但该 revision 只驱动资料库结果；`:594` 的 Reader 未接收它，
  也没有相应 `conversation-search` 缓存失效。
  `annotation-workspace.tsx:89–92` 远程写入只使详情查询失效；
  `apps/web/components/query-provider.tsx:9–15` 的过期时间本身不会定时刷新挂载查询，
  且窗口聚焦刷新关闭。
- **用户后果：** 编辑／删除批注后，资料库大搜索可以更新，而已经打开的当前
  对话面板仍可能显示旧评论或旧命中，造成“改了但还搜得到”的不一致。
  这不是重复报告已补的 worker 订阅，而是其上层缓存边界。
- **建议：** 在内容更新／索引代际发布时，窄范围失效当前来源及对话的搜索查询，
  同时隔离旧请求发布；检查远程写入的对应通知。不要靠重挂载整个 Reader、
  刷新整页或清空全站缓存来实现。
- **验收：** 保持面板打开、或关闭后立即重开，编辑／删除批注都能自动反映最新结果；
  旧异步响应不能复活删除项；账户失效与来源切换仍受访问代际约束；
  只更新阅读位置不触发全文重建，不改变草稿和阅读位置。

#### STATE-UPLOAD-QUEUE · 从“整批重选”增强为逐项重试与取消

- **维度／类型：** 系统状态、错误恢复；Opportunity。
- **严重度／置信度／工作量：** Medium；Observed (code)，恢复收益 Inferred；M。
- **位置／证据：** `apps/web/features/attachments/conversation-files-panel.tsx:170–227`
  创建会话后逐文件上传，`itemIds` 仅在本次函数中；进度以文件名作 key，
  文件阶段失败提示重选，finally 清空进度。
  `apps/web/lib/api.ts:141–166` 已返回 XHR `cancel`，当前面板只使用 promise；
  `:176–177` 也已有上传项删除 API。现有代码已经区分文件阶段、确认阶段和
  结果未知，**并非没有进度或未知结果恢复**。
- **用户后果：** 大批次中后续文件失败后，需要重新选择整批，无法在现有界面
  保留已接受项并单独重试失败文件；也没有用户可见的正在上传取消入口。
- **建议：** 维护本次访问内的有界队列，以稳定项身份而非文件名记录进度和接受回执；
  使用已有取消句柄，允许仅重试失败项。最终确认结果未知时先核对，不盲目重放；
  会话过期要明确重开，不顺便做服务器孤立资料清理或磁盘清理。
- **验收：** 第三个文件失败时前两项回执保留，只重试第三项；同名文件互不覆盖；
  取消会终止在途上传且不自动 finalize；切换对话后的迟到回调不可发布到新范围；
  finalize 超时仍走原来的未知结果核对路径。

#### STATE-COPY · 分享面板复制缺少成功／失败闭环

- **维度／类型：** 反馈与恢复；Defect／反馈缺口。
- **严重度／置信度／工作量：** Medium；Observed (code)，浏览器行为 Inferred；S。
- **位置／证据：** `apps/web/features/sharing/share-panel.tsx:91–95` 及 `:298–303`
  直接调用可选 `navigator.clipboard?.writeText`，没有局部成功／失败状态；
  API 不存在时静默结束，权限拒绝时没有这里的异常恢复。
  `apps/web/components/use-clipboard-copy.ts:7–31` 已提供 copying／copied／failed、
  文本身份隔离和手动选择兜底，其他分享管理表面已有可复用模式。
- **用户后果：** 用户无法知道复制是否成功，可能离开面板后才发现剪贴板没有链接。
  这是局部分享面板问题，不是全站所有复制操作都失效。
- **建议：** 复用现有 hook，提供可选中、只读的完整链接以及明确反馈；
  失败文案如“未能复制，请选择链接后手动复制”。不新增剪贴板依赖，
  不把实际 token 写进日志或审查证据。
- **验收：** API 缺失、拒绝、成功三种情况都有正确反馈与可用链接；
  旧复制完成不能让新链接显示“已复制”；面板关闭／切换不遗留旧反馈。

### 导航与结果完整性

- **维度／类型：** 数据显示与导航；Opportunity，沿用既有暂缓项，不是新增缺陷。
- **严重度／置信度／工作量：** Medium，按长对话需求进入；Observed (code)，

- **位置／证据：** `apps/web/features/search/conversation-search-panel.tsx:120–135`
  只请求 `limit: 50`，`:202` 显示展平后的数量而没有后续页入口。

- **用户后果：** 高频词可能只显示前一批结果，当前数量又没有清楚区分“文档数”
  和“命中位置数”；不能由这个数量推断完整结果。
- **建议：** 有界“加载更多”，明确显示前 N 项／还有更多，必要时增加兼容的

  小查询不增加无意义请求，旧离线包继续可读。

## 6. 建议顺序与批次边界

1. **先做分享小批：TRUST-EXPIRY + STATE-COPY。** 同一表面、范围小，
   分别验证“不会意外永久”和“能确认拿到链接”，不改分享 URL 或授权模型。
2. **输入安全独立批：FORM-COMMENT-DRAFT。** 先明确草稿生命周期、账号／标签页
   归属和保存回执，再做持久恢复；不要与附件队列混成一套新通用状态框架。
3. **结果新鲜度独立批：STATE-SEARCH-CACHE。** 接续当前索引生命周期，
   先核验并补足当前对话面板缓存层，不再添加匹配模式。
4. **完整性分小批：NAV-TOC-PAGE、NAV-OFFLINE-REFERENCES；有需求再带 SEARCH-CAP。**
   共用真实锚点原则，但分页合同和各自专项验收分开，不统一提高上限。
5. **按使用需求进入：STATE-UPLOAD-QUEUE、DATA-PREVIEW-BOUNDS、
   NAV-CONVERSATION-PAGE。** 分别对应批量附件频率、超预算资料和库规模；
   无需等待规模实测才能补诚实的数量／预览范围文案，但不提前重构大列表。
6. **STATE-SEARCH-SCALE 保持条件项。** 获授权后先测量，确有瓶颈才进入实现。
7. **DATA-DOCS 可独立小修。** 不与产品修复的完成数量／性能收益合并统计。

这些是选项和验收边界，**不是全部执行或发布授权**。
现有三批未提交搜索工作仍需在后续明确授权下按各自验证合同验收；
“运行门禁”“CI 通过”不能再作为新增优化方向凑数。
不恢复 `CONTINUOUS_OPTIMIZATION_BACKLOG.md` 中已移除的泛化候选。
