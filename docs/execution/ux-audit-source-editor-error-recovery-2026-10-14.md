# 源码编辑器错误恢复审查（2026-10-14）

## 范围与证据

本批审查阅读器内 Markdown 源码编辑器的保存、关闭未保存附件和加载最新状态
恢复路径。证据来自当前源码，未启动本地应用，因此“用户会看到底层错误”是
基于错误对象传递到渲染节点的代码观察，不是运行截图结论。

## Findings

### EDIT-ERR-01 — Medium / Observed (code)

保存失败时，编辑器直接把 `Error.message` 放入红色提示。API 客户端对部分
4xx 仍保留服务端原文，上传/清理回调也可能传回底层错误；中文界面可能出现
英文或技术细节，英文界面可能出现中文。错误提示没有稳定区分冲突、暂时不可用、
资源不存在和输入限制，读者难以判断下一步。

### EDIT-ERR-02 — Medium / Observed (code)

加载最新状态失败和关闭未保存附件失败也直接渲染原始异常消息。源码草稿本身
仍会保留，但恢复入口旁的错误文案不稳定，且关闭清理失败可能让用户误以为
附件状态已经完成处理。

## 处理决策

- 在编辑器边界将错误归类为冲突、连接/服务暂时不可用、消息不存在、内容限制、
  附件处理失败或未知失败，并按界面语言显示稳定、可操作的提示。
- 继续用原始错误内容判断是否为版本冲突，但不直接把原文显示给用户。
- 保留当前源码、附件草稿和“加载最新状态”入口；不自动重试、不自动覆盖草稿、
  不改变上传、删除、保存或权限语义。
- 只改编辑器显示层和错误分类，不改 API、数据库、migration、轮询、网络次数
  或资源预算。

## 验证边界

按用户当前要求，本批不启动服务、不登录、不运行浏览器、lint、typecheck、build、
测试、CI 或部署；后续由用户自行验证。
