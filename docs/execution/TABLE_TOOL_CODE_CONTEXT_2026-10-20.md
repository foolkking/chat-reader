# 表格源码的代码上下文与容器保真 — 2026-10-20

状态：持续本地优化；目标保持活动、无 Token 预算上限。不推送、不启动 CI、
不部署。无新增依赖、API、migration、导出/离线数据协议变化。

## 已复现的问题

上一轮五个合成 GFM 诊断显示，手写围栏状态没有真实引用/列表容器语义：
顶层代码中的引用或列表样式文本可能被误当作闭围栏，暴露内部表格；离开一个
未闭合的引用/列表代码容器后，又会误拒绝外层表格。原始输入及失败在
[键盘续查](TABLE_TOOL_NAVIGATION_2026-10-20.md)中保留。

新增回归在产品修复前得到 **26 通过 / 1 失败 / 0 跳过**。旧 500 个样本与
旧扫描器一致，只证明复刻了旧规则，不能当作 GFM 语义已经正确的证据。

还发现列表中的四空格表格被单独预览时丢失了父列表上下文，从而显示成代码；
原表格实际不是代码，用户却无法编辑/应用。

## 实现与边界

1. 删除第二套围栏状态扫描，使用已安装的 CodeMirror Markdown 代码块上下文，
   同时识别 `FencedCode` 和 `CodeBlock`。不改共享 Reader 渲染器或 canonical 文本。
2. 工具打开/刷新时冻结源码和已解析覆盖位置，复用编辑器维护的语法树。
   对话框识别及最终 Apply 使用同一快照；源码不匹配、覆盖不足或树长不足时
   不复用。后台正文仍受原 revision/stale 保护，不能拿旧上下文覆盖新正文。
3. `ensureSyntaxTree` 可推进现有增量解析，50ms 是库的工作提示，不是硬实时保证。
   不在每次单元格输入时重复构建全篇 AST，也不建立全局/历史正文缓存。
4. 无可用编辑器上下文的独立调用，只解析前文到表头行末，不解析表格体或后方
   正文。该成本仍随前文规模增长，不声称任意巨大前文都廉价或内存恒定。
   表格片段原有 1 MiB/5,000 行/200 列/50,000 单元格限制不变，不截断源文。
5. 明确完整选区仍可编辑代码表格；自动光标识别不能绕过代码保护。
   无法识别时用一句恢复说明要求完整选区，不再误导用户把光标重新放回表格。
6. 富预览只序列化已确认的表格本体，不携带脱离父结构的容器前缀。下方 Markdown、
   完整应用序列化及 CodeMirror transaction 仍保留原引用/列表前缀和换行约定。
   这不是把实际源码表格提升到外层，也不新增界面模式。

接入中的一次上下文覆盖回归为 **69 通过 / 1 失败**：声明覆盖完整源码、但树
实际较短时仍可能被复用。补齐树长与覆盖位置一致性检查后解决；此失败保留，
不归类为测试适配器错误。测试加载器仅改为解析已有真实 CodeMirror 模块，
没有提供绕过代码判断的 parser stub。

  用大量无关后文验证独立解析输入止于表头，而不是完整文档。
- 四个新增真实工作区场景验证：代码样式伪闭围栏及缩进代码不可自动编辑、
  引用/列表外表格能编辑并一次撤销、列表表格预览/缩进保真、明确代码选区保留
  围栏。在所检查的冻结树路径中，透明包装实际 parser 的 `.parse` 观察到零次
  独立上下文重解析；这不表示编辑器从未执行后台/增量解析。
- 实际工作区依旧只改草稿；用例验证无意外服务端写入，并保留旧 37 个场景。

本地 Chrome 仍运行实际 workspace/form/CodeMirror、dialog、焦点、共享 renderer
和 CSS，API、Next loader、assistant-ui 源传递及无关 UI 是显式合成适配器。

全界面可访问性评分、辅助技术或真实手机验收。源码、输入、日志和回执摘要见
[独立证据](../evidence/table-tool-code-context-2026-10-20.json)。

认证后端、服务器 OOM/低内存压力与跨设备性能仍不是本轮验收结果。后续继续按
