# 阅读可靠性 CI 续查 — 2026-10-31

## 范围与证据

本次是批准计划的验收续查，不是全产品重设计。平台为响应式 Web；
用户需要在手机或桌面筛选自己的待读对话和批注，然后回到正文。
审查依据为 run `41183167236`、源码 `53d0e22` 的合成浏览器证据、
共享筛选组件与测试源码；不使用真实用户正文，不运行本地浏览器。
未检查生产认证界面、实体触摸设备、屏幕阅读器或完整 WCAG 合规性。

## 重点结论

1. CI 失败不能全部归为产品坏了：两条批注用例使用的精确 label
   定位没有命中快照中实际存在的 `combobox "Type"`；改用真实可访问角色。
2. 移动端清理测试错点抽屉后面的浮动任务摘要；改从真实侧栏 Tasks
   入口打开同一个 Task Center，不强制点击、不跳过审查断言。
3. 截图确实暴露筛选布局缺陷：项目下拉框挤压了关键词输入框。
   这不是测试定位问题，需修复共享组件并保留窄屏回归。

**FORM-01。** `/annotations` 的 375×900、英语、深色、五条合成批注截图中，
`Keywords` 下方输入框只剩窄条，`Project` 下拉框仍占据同行大部分空间。
源码 `apps/web/components/collection-view.tsx:65` 使用零基础宽度的伸缩
搜索表单，而项目控件保持较大固有宽度。用户难以查看或编辑筛选文字。
建议窄屏让搜索表单独占一行；宽屏保留共享筛选工具栏和自然换行。
不新增颜色、字体、控件体系或断点。

## 保留与验收

保留已分开的原文摘录／评论、失联批注的复核链接、URL 筛选状态、
44px 控件高度和原有纸面／石墨／海绿 token。手机检索应优先于元数据，
不以缩小字体、隐藏项目筛选或制造横向页面滚动解决空间问题。

下一次 CI 必须验证输入框可读宽度、输入与提交、所有批注类型筛选、
项目与排序参数和 375/1440px 截图；不得把“页面无横向溢出”当作全部可用性证据。
滚动容量测试的 120px 回退另由执行记录追踪；截图不足以确认其唯一根因。
