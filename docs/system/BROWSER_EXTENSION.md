## 长对话采集与进度 — 0.3.0 已交付

本节和下方使用说明描述 0.3.0。对应 Reader `7c4574b` 与插件 `e18bb4c` 的精确 CI、分发及安装文件已核验；**真实个人 ChatGPT 账号采集和浏览器重新加载后的操作仍由用户验收**，不把合成来源或文件替换当作这项验收。

- **取消采集硬门槛，而非把数字改大。** 不再按 8 MiB 单次／32 MiB 累计 JSON、16 MiB 单附件、100 MiB 包、2 MiB 单正文、50,000 条消息或 128 个隐藏路径节点拒绝完整采集。Fork 仍负责来源请求、解析与转换；新适配器按文件字节范围索引，逐条转换当前分支。消息以至多 65,536 UTF-16 码元（不切开代理对）、附件以 192 KiB 发送到扩展私有上下文；正文、索引及 ZIP 分块写 OPFS，资源链校验与 ZIP 摘要随写入生成。对话不拆成多条 Reader 记录，来源登录凭据不进入 Reader 或任务账本。
- **进度属于主要保存路径。** 保存按钮旁显示「读取对话 → 核对来源 → 整理消息 → 接收附件 → 生成导入包 → 上传到 Reader」，包含实际页数、条数或字节；总量未知不显示百分比。阶段切换立即显示，阶段内合并频繁事件但保留末次计数。仅允许有限的阶段／数字字段穿过 UI 边界，不把来源标题、文件名、链接或会话凭据作为进度上传。虚拟列表加载历史不再误清当前保存票据；真实来源／分支变化仍使旧采集失效。
- **持久化续传。** `capabilities.resumable_capture=true` 才开始新采集；旧实例明确提示先升级 Reader，不静默退回旧整包路径。`POST /api/extension/v1/transfers/{key}` 绑定设备、用户、目标、总字节与 SHA-256；`/chunks` 每次至多 4 MiB，校验并 `fsync` 后才确认偏移；`/finish` 校验整包后进入原分析任务。重试先查原 `requests/{key}`，不生成另一个导入。已封口包在网络中断后保留，可从原任务继续；未结束的来源读取在标签页关闭后不能假装恢复。取消只能移除未受理的暂存包，不能删除已入队数据。换账号清理旧设备本地未完成暂存，不将其提交给新账号。
- **没有绕过真实容量与完整性保护。** `effective_import_size_mb`（实例配置及账号政策，默认 500 MiB）、归档条目／元数据检查、64 MiB 导入工作区、浏览器 OPFS 和磁盘余量仍有效；超额、空间不足、断网、缺件、授权失效分别反馈。选择性追加仍是最多 250 条的独立人工复核合同，不将它与完整对话采集混为一谈。
- **兼容与上线顺序。** 此续传协议复用 `ImportRecord`，自身不增加 migration；同一工作树的短码配对另有 `20261125_0065`，不能漏掉。先交付配套 API/worker，再更新保留 ID 的插件。长正文内部草稿新增摘要旁文件，旧程序不能消费新草稿；切回旧 API/worker 前必须完成或保全这些任务，不能把未完成草稿直接交给旧 worker。见[内部草稿合同](ADAPTIVE_IMPORT_CONTRACT.md#reader-long-message-candidate)。

[采集专项证据](../evidence/extension-capture-2026-11-25/README.md)包含真实 ZIP 跨仓校验、隔离 PostgreSQL 并发收据和 Edge 合成页面。当时未部署；后续部署以顶部交付回执为准，仍未进行真实 ChatGPT 账号端到端采集或 Chrome 本轮实机验收。

## 统一设计 v2 — 0.3.0 已交付

修复前逐项问题保留在[设计复审](../execution/ux-audit-extension-design-v2-2026-11-25.md)。本节是代码合同，不把原型或合成来源当作真实账号验收。

[最终本地复核](../evidence/extension-design-2026-11-25/README.md)逐项对照20个设计状态，保留失败与未知；后续精确 CI、发布和原位替换见顶部交付回执，不改变下述真实来源边界。

- **资料库仅搜名称。** 新客户端显式请求 `conversations?match=names`，仅匹配显示标题或所属非归档项目名；先分页，再统计本页附件。`catalog_names` 缺失则明确提示升级，不静默回退全文搜索。旧客户端不带 `match` 时仍保留原合同。主 Web 全文搜索不变。
- **不再占用原生侧栏。** 已批准的 ChatGPT 私人页面使用共用右侧把手，浮层切换当前对话/Reader 资料库；不改正文宽度、边距或滚动容器。普通网页无注入，主动点工具栏打开独立 `center.html`。打包器移除 `sidePanel`，使用绿色 cr 16/32/48/128 图标，公开扩展 ID 不变。私有列表和短码在扩展页面内，不放入来源 DOM；动态 WAR 的稳定扩展 sender 身份必须同时通过一次性票据、标签、父文档与路径检查。
- **短码配对。** 扩展原位显示 10 分钟一次性短码；用户在 Reader `/extension/devices`（账号安全入口）核对账号、设备与权限后批准。只有短码不能领取 token；另有高熵领取凭证、速率限制和单次轮询领取。旧 PKCE/有效设备继续兼容。签发时重新锁定并验证实际 Web session，不能把密码变更/会话撤销前的请求升级为新的设备授权。
- **当前对话索引无需 Reader 登录。** 轮次、真实章节、所属附件、全文每处匹配；实际 DOM Range/章节/文件目标可见才算定位。按消息从原来源 Blob 按需读取正文；持久导航模型只保存轻量元数据，搜索保留每 64 处的稀疏游标及当前页片段，不缓存整段正文数组。手动输入取消旧跳转；不可确认的附件仅明确定位所属消息。未知目录明确为部分目录。
- **独立四步导入中心。** 来源 → 跨项目/筛选/分页勾选 → Reader 目标与附件范围 → 实际任务。来源未连接 Reader 也可本机浏览；确认上传前必须授权。默认零勾选，从项目进入只是提示。项目与对话按标识选择，同名不认领；未知归属不是未归类。映射只在勾选“记住”后按来源范围、目标实例和账号保存。
- **两种来源不混称。** 网页适配只读取用户明确选中的私人标签页已挂载目录链接，不枚举新的内部目录端点，不宣称整个账号/项目。只有会话中能够明确核实用户与工作区标识时才启用批量读取；否则目录可看、发送被阻止，提示使用官方包。真实工作区字段和平台适用条件未独立验证，不将合成页面通过称为全量网页来源已验证。官方 ZIP 在本机按中心目录读取、CRC/压缩长度验证、逐项解压到 OPFS，按文件范围索引 `conversations.json`。只发送选中的消息与可证明归属的文件；不上传整个原包，不按同名文件猜资源，不因缺件显示完整成功。
- **固定计划与原收据。** 确认后锁定来源范围、会话 ID、目标项目、附件策略和每项幂等键；默认逐条读取/封包/续传。关闭中心不取消已接收任务；未发送计划保留，重开/重启需重新核实原文件指纹或原工作区。结果不明先查原键，不新建副本。只确认共同前缀才自动末尾追加；缺件、分享或分支/原文改变仍需逐项复核。换 Reader 账号/来源范围暂停，未确认的上传不能被当成可安全取消的“未发送项”。
- **大批次仍可核对。** 选择与任务列表每页50行，支持本页／筛选快照、跨页保留、已选移除和状态筛选；附件索引每页64行，均非总量上限。整个项目仅限身份和归属完整的本地导出包。确认前可主动核对所选来源的既有绑定，不以绑定冒充内容一致；删除目标禁止回落未归类。冲突可跳过本次并保留原件、原收据；新计划不能覆盖未完成项。领取、取消、恢复和清理在实际锁内重查账本，页面关闭不决定服务端结果。
- **窄重试合同。** `import_retry=true` 才调用 `POST /imports/{id}/retry`。只重试原用户/设备的失败或暂停分析、保留来源及可重建预览；原收据不变。失去原始来源、仍执行、已提交或选择性追加拒绝。清除旧批准后重新生成预览，不自动沿用对实时分享/缺件/冲突的同意。复杂失败需在 Reader 核对，不包装成已成功重试。
- **交给 AI。** 未显式保存预设时默认完整对话、可导出的附件原件、已有 Current/Index；已保存的预设保持原选择。网页与扩展共用账号预设及乐观版本检查。扩展下载使用服务端安全的 `对话名.context.zip`；上下文包与接续 Skill 下载分开，取消 Skill 不重新生成上下文包。两端显示实际附件/交接文件结果，不传回来源网页。设置写入与 Web 预设更新共用 collection→preferences 锁序。

### 升级边界

必须先交付 Reader API、worker、Web（单一 Alembic head `20261125_0065`），再替换同 ID 的扩展；`king` 已按此顺序完成。其他实例仍须独立通过签名、容量和恢复门槛。0064→0065 属于完整维护更新；保留现有配置及至少一套验证恢复点，不承诺本轮 15 秒更新，也不自动清理唯一备份。新内部正文旁文件不能交给旧 worker 消费。

## 安装、连接、撤销

1. 运维在实例首次接入或能力升级时部署同一签名版本的 Web、API 和 worker，并迁到对应 Alembic head。`v0.1.10` 为 `20261125_0065`（此前 `v0.1.7` 为 `0064`，P0–P2 为 `0063`）。已获得本实例私有安装包的用户直接看第 3、4 步。旧 schema 需要按[完整维护流程](../deployment.md)升级，不能走“只换 Web”。不覆盖已有配置、数据库或卷。
2. 保持正常 Reader 登录：`AUTH_ENABLED=true`，使用本实例自己的强 `AUTH_SESSION_SECRET`，`PUBLIC_WEB_BASE_URL` 与实际入口一致。在现有 API **和 worker** 的环境中设置 `READER_EXTENSION_IDS=gihbiofiiflkckcmomddkkjkoifkddfi`。默认空值：扩展 API 不可用。没有域名通配和跨站 Cookie 要求。不要把个人密钥交给扩展。
   **从 v0.1.5 首次接入：只改 `.env` 不够。** 该版本的标准 Compose 不把这两个扩展选项传入容器；在线更新也不会替换运维配置。对照新版 `docker-compose.production.yml`，仅在现有 `&api-environment` 加上 `READER_EXTENSION_IDS: ${READER_EXTENSION_IDS:-}` 和 `READER_EXTENSION_CAPTURE: ${READER_EXTENSION_CAPTURE:-true}`（自定义 Compose 则核对 API、worker 的实际环境）。保留已有变量和挂载；在维护前验证配置但不要打印渲染后的完整配置。安装后以已授权设备实际读取能力为准，不把登录页 `200` 当作扩展已接通。
3. **首次安装：**解压运维提供的本实例 ZIP（已经解压则跳过），在扩展管理页选择「加载已解压的扩展程序」，选直接包含 `manifest.json` 的目录，不选 ZIP 本身。接着按第 4 步连接。**原位更新：**可信新包替换原目录后，在扩展管理页点「重新加载」，再刷新 ChatGPT；目录保留旧版本名称不影响 `manifest.json` 中的实际版本。不要为了更新先卸载，以免清除本地授权和任务状态。

   **仅打包者：**在 Fork 根目录运行（最后一个参数必须是**尚不存在**的目录；使用真实 Reader 的精确 HTTPS origin，无末尾斜杠）：

   ```powershell
   node scripts/package-reader.cjs https://reader.example.test E:\chat-reader-temp\reader-private-build --zip
   ```

   `--zip` 在输出目录旁另生成 `chat-reader-0.3.0.zip` 和 SHA-256 文件，不覆盖已有文件。收到运维提供的包时**不必编译**：与可信交付记录核对 SHA-256，解压到一个准备长期保留的目录。在 Chrome 或 Edge 的扩展管理 → 开发者模式 → 加载已解压的扩展程序，选择**直接含 `manifest.json` 的目录**，核对 ID 和实例地址。示例域名和验收用回环包都不是生产安装包。仅本机测试允许 `http://127.0.0.1:端口` 或 `http://localhost:端口`；两个 hostname 不互换。此构建不影响 Fork 原版导出器。
   公开 Fork 不公开实例网址，也不提供可直接连入网站的制品；推送 CI 保留 `reader-reference-<SHA>-<运行 ID>-<尝试>` 参考摘要。由运维私下制作实例包，用 Fork 的 `scripts/verify-reader-distribution.cjs` 对照已核验的精确成功运行，再只向用户交付实例 ZIP 与**实例 ZIP** 的摘要。不能把示例 ZIP、参考摘要或本地实验包当成安装包；不必为此在公开仓库设置站点变量。
4. 点 Chat Reader 的 **连接 Reader**，扩展原位显示短码。自行打开 Reader **设置 → 账号安全 → 浏览器插件**，输入短码、核对账号、设备和权限后批准；不在扩展输入 Reader 密码，也不弹出登录窗。有效旧设备不必重新连接，旧版 PKCE 仍兼容。确认新导入的目标项目后，在 ChatGPT 当前对话点「保存到 Reader」即可。打开正文仍走普通网页登录：浏览器登录了另一账号时，不用扩展授权替它打开私有内容。
5. 改默认目的地或换账号：打开浮层或独立中心的设置；换账号先断开设备再重新授权。项目名默认不显示在第三方页面；可在此明确开启。远端撤销：Reader **设置 → 账号安全 → 已授权的浏览器插件**。若运维关闭 `READER_EXTENSION_CAPTURE`，只禁止新采集；保留获准的资料浏览、已接收的任务、手动 ZIP 和 Context 导出。要停用整个设备面，清空 `READER_EXTENSION_IDS`。

当前每个账号最多有 32 台有效插件设备；达到上限时新授权以 `409` 拒绝。授权页明确说明需在「设置 → 账号安全 → 已授权的浏览器插件」撤销旧设备，再返回重试；该界面区分设备上限和未登记扩展，不向用户暴露原始服务器错误，也不提高设备数量限制。

## 两条日常路径

| 任务 | 行为 |
|---|---|
| 找资料 | ChatGPT 私人页面的右侧把手展开浮层，切换到 Reader 资料库；普通网页不注入界面，工具栏打开独立中心。资料库只搜显示标题或所属项目名称，支持最近／已置顶、项目筛选及分页。「最近」按在 Reader 打开的时间；在此范围还没打开过对话才显示「最近更新」。标题打开 Reader 新标签；附件不独立占行。当前对话索引的本地正文查找是另一入口，不改变资料库名称搜索。 |
| 整理 | 行末 `…` 可移动项目、设置全局或项目内置顶。有附件可在 Reader 查看；若仅有一个匹配的有效附件就定位它，否则打开该对话的文件面板。在 Reader 修改文件显示名，不改字节。没有删除、分享、批量处理或管理员权限。 |
| 保存 | 选定默认目的地后，在当前对话点一次。正在保存不能重复点击。只有本次完整提交才显示「已存入 Reader」；重访只能证明以前存过时显示「打开已存版本」。本地没有收据时，默认不发送来源标识。可在页内更多菜单主动「查找已存版本」，或在插件齿轮中单独允许此设备自动识别。自动识别只查询当前可见对话的来源 ID，不传正文、不扫描其他对话；服务端找到可访问的绑定后也只显示「打开已存版本」，不声称当前分支/内容相同。缺附件确认后仍显示「部分已保存」。冲突可另存；不会覆盖原件。展开状态可见实际动作和实际项目。更改默认目的地不会移动已有对话。 |
| 只追加一部分 | ChatGPT「保存到 Reader」旁的更多 → **选择内容并追加到…**，先在本机勾选消息，再在 Reader 选择自己可写的目标。若从 Reader 已有对话 `⋯ → 追加导入内容` 进入，目标已经固定，选择文件再勾消息。两条路径都先展示目标的当前末尾，最后一次点击才提交。 |
| 查任务 | 无任务时不占首屏；必要的复核在资料列表上方，历史在 **齿轮 → 最近任务**。来源读取未结束就关标签页，需要回到来源重试；Reader 已接收则由服务端继续。上传结果不明，先查询原收据。 |
| 接续上下文 | 对话 `…` → **交给 AI · `.context.zip`**；Reader 正文也保留快捷入口。两端共用账号预设和生成器：无自定义预设时默认完整对话、可导出附件原件、已有 Current/Index，明确保存过的选择不覆盖。包可能含当前用户批注和笔记；实际缺件/超限如实反馈，失效预设不能默默放宽。完成后分别提供对话名上下文包和接续 Skill 下载，只下载给用户，不传回 ChatGPT。 |

项目内没有搜索结果时，可保留原词搜所有项目；「包含未置顶对话」只解除置顶条件，不重置项目。资料库首次读取失败时可直接重新读取，不需要再次授权；项目清单未核实前不能确认默认保存位置，但仍可在设置中断开设备。置顶、移动正在等待结果时不会重复执行；结果未明时不会自动重试。

同源对话再次保存时：完全相同返回原件；只有已绑定、未改写的可验证树路径才能追加。不能证明安全（包括已归档、已删除、本地改过正文或附件、分支不同、旧手动导入身份不足）时，不动原件，可以另存。追加到**仍有效的整条实时分享**前要单独确认，worker 落库时再查一次。网页来源无法证明项目/账号全量清单，只能选已发现且有权读取的项；本地官方包的整项目选择须满足上文身份、归属和目录完整性条件。

**选择性追加不是同步或覆盖。** 每次最多 250 条，按来源次序而非勾选先后追加。取消本地选择不会下载附件；无从证明原提问时，回答作为独立轮次，不编造上一条提问。已追加的相同条目跳过；来源内容变化时，必须明确选择把新版本另加在末尾。实时分享和已知缺件分别确认。其他设备先改了末尾，保留勾选并显示新的末尾，必须再次确认。来源格式需要辨认时，沿用既有映射验证，不转成普通新建导入。

**接到收据以后可以离开。** 在 Reader 确认的追加已受理后，同一账号重新打开该任务，会看到当时选中的来源对话、消息和目标。若排队期间目标发生变化，后台不追加任何一条；再打开时展示新的末尾，不自动发送第二次确认，也不沿用针对旧末尾的分享或缺件同意。尚未提交时的页面勾选不是可跨刷新恢复的草稿。

**配套能力，不靠版本号猜。** `/api/extension/v1/capabilities` 除原 v1 字段外提供 `catalog_details`、`save_receipts`、`source_lookup` 和 `selective_append`。完整保存的结果记在已有导入记录；选择性追加使用 `20261123_0064` 的逐条收据。设备令牌只能暂存所选片段，不能直接追加到任意目标；Reader 账号确认和 worker 执行时都检查归属及授权。片段不参与完整对话的来源绑定。只有真实提交才记录新建／未改／追加（条数）／另存及保存时的项目；读取时另行核对现有归属。缺失旧回执或完整性未知时不能显示完整成功；追加不会自动修复既有缺件。无本地收据时，`source_lookup` 仅在用户主动查找或为当前设备开启自动识别后，才向 Reader 查询当前可见的来源 ID，不读取正文、不枚举历史；找不到、无权或不支持该能力时不提供打开链接。查询成功只证明存在可访问的旧记录，不证明当前内容相同；用户要保存当前版本仍须经过原有来源、分支及完整性审查。[选择与末尾争用验收](../evidence/reader-extension-append-2026-11-24/README.md)与[改前审查](../planning/ux-audit-reader-extension-2026-11-23.md)分开记录。

## 实现合同

* **账号**：0.3.0 使用上述 10 分钟短码及独立高熵领取凭证；旧一次性授权码（2 分钟）+ S256 PKCE + `state` + 固定公开扩展 ID / HTTPS 回调继续兼容。设备 access 有效 10 分钟，refresh 单次轮换、有 30 天绝对期限。服务端仅存绑定实例密钥的摘要；禁用账号、凭据版本变化、撤销或实例密钥轮换都会拒绝。只有专用 `/api/extension/v1/` 接受设备 bearer；Cookie 不替代 bearer，设备 bearer 也不授权普通 Web API。所有数据操作由服务端按真实 `user_id` 校验；根管理员设备也没有管理权限。
* **浏览器**：来源脚本仅在当前对话接受真实点击；不读普通网页、浏览历史、Cookie 库，不同步凭据。页内只知道当前传输的票据（绑定标签、文档、路径和设备）。有权限的扩展上下文连接构建时固定的 Reader。来源会话和原始响应不进入 ZIP、Reader、设备任务账本或日志。不会自动过滤用户自己写进正文的隐私内容。公开扩展 ID 不是对本地安装包的签名：只安装可信构建。
* **打包与内存**：复用 Fork 的可见分支解析、分页去重和资源识别；可用的静态 Markdown 保留，不可还原的卡片/资源须复核。源附件按件读取，在内存小或容量未知时一次一件，条件允许最多两件；向扩展私有临时目录逐块发送并等接收确认，不把整个 ZIP 转成 Base64。0.3.0 取消旧 0.2.0 的 8/32 MiB JSON、16 MiB 资源、约 100 MiB 采集和 2 MiB 单消息门槛；分块方式和仍保留的真实资源保护见[长对话采集](#capture-streaming-candidate)。未重新加载的浏览器仍可能运行旧代码。
* **Reader ZIP**：根部 `conversation.md`、`manifest.json`、逐行 `reader/source.jsonl`、以及声明的 `assets/`。按 UTF-8 **字节**范围和 SHA-256 校验正文，不以标题行推断消息；树来源记录源消息 ID、相邻展示消息和真实树节点段。列表来源不冒充树。资源按固定 256 KiB 块计算链式 SHA-256；验证成员集合、大小边界、正文中的引用、字节和每条消息的资源归属。另走原归档目录安全、资源扫描及 canonical 持久化。普通／低内存导入用同一协议；旧格式仍走原路径。
* **提交与恢复**：共用原有上传收据、分析任务、单 worker、资源等待和原子提交。用户＋来源绑定、PG 事务锁、canonical 状态及分享状态决定行为。审阅收据同时绑定制品、目标项目和分类版本；完全相同的竞态是无写入操作。后台不按名称合并、不覆盖批注/书签/接续笔记或已有项目。任务终态才显示保存成功。来源资料**不是**远端内容真实性的数字签名。
* **备份**：物理 PG 备份包含新增表；恢复到另一个实例时须在对外开放前轮换实例密钥并重新登记可信客户端。个人/系统逻辑 `.cr` 的显式业务表清单不导出设备授权，不视为设备绑定的备份。逻辑恢复若失去来源绑定，不按标题认领旧对话；原件优先保全。

**原标签换账号：**手动查到的历史版本只对当前设备、来源、标签和文档有效。换到另一 Reader 账号后，原 ChatGPT 标签也不继续显示旧账号的「打开已存版本」。当前“已找到”不是后台同步承诺；点击打开时仍检查当前账号是否有权访问。[中英文浏览器复核](../evidence/reader-extension-append-2026-11-24/delivery-check.md)

## 已交付范围与后续边界

0.2.0 的 P0–P2 是私有内测范围，没有远端项目/账号枚举。0.3.0 增加的本地包与已发现网页项路径见[统一设计合同](#unified-candidate)，仍不宣称完整远端枚举。真实项目标识、分页终点、失权与平台适用条件需单独授权样本验证；不能证明完整时只展示实际发现内容。后续分发仍必须经完整 CI 与安装包核验，不为验证去读取私人资料或在生产演练。
