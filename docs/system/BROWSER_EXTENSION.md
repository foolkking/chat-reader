# Chat Reader 浏览器插件（桌面 Chrome / Edge 私有内测）

插件是本实例的客户端，不是第二个文件库。扩展的采集、资源转换及界面在 `foolkking/chat-intelligent-ui-exporter` 的 `codex/reader-extension` 分支；本仓库负责账号、数据归属、导入和导出。两边的合同名是 `reader-chat-v1`。**生产 `v0.1.5` 不包含本功能；不能仅安装扩展后就连接旧站。** 见[隔离验收记录](../evidence/browser-extension-2026-11-23/README.md)。

## 安装、连接、撤销

1. 在**测试实例**安装本分支对应的 Web、API 和 worker，数据库迁到 `20261123_0063`。原来是 `0062` 的实例需要按[完整维护流程](../deployment.md)升级，不能走“只换 Web”。不覆盖已有配置、数据库或卷。
2. 保持正常 Reader 登录：`AUTH_ENABLED=true`，使用本实例自己的强 `AUTH_SESSION_SECRET`，`PUBLIC_WEB_BASE_URL` 与实际入口一致。在现有 API **和 worker** 的环境中设置 `READER_EXTENSION_IDS=gihbiofiiflkckcmomddkkjkoifkddfi`。默认空值：扩展 API 不可用。没有域名通配和跨站 Cookie 要求。不要把个人密钥交给扩展。
3. 在 Fork 根目录运行（最后一个参数必须是**尚不存在**的目录；使用真实 Reader 的精确 HTTPS origin，无末尾斜杠）：

   ```powershell
   node scripts/package-reader.cjs https://reader.example.test E:\chat-reader-temp\reader-private-build
   ```

   在 Chrome 或 Edge 的扩展管理 → 开发者模式 → 加载已解压的扩展程序，选择输出目录，核对 ID。仅本机测试允许 `http://127.0.0.1:端口` 或 `http://localhost:端口`。**两个 hostname 不互换**。此构建不影响 Fork 原版导出器。
4. 点工具栏的 Chat Reader → **登录并连接**。在 Reader 自己的页面核对实例、账号和权限，再授权。确认新导入的目标项目；之后在 ChatGPT 当前对话点「保存到 Reader」即可。可关闭所有 Reader 标签页。打开正文时仍走普通网页登录：浏览器登录了另一账号时，不用扩展授权替它打开私有内容。
5. 改目的地：展开侧面板「保存到…」。换账号：先断开设备再重新授权。远端撤销：Reader **设置 → 账号安全 → 已授权的浏览器插件**。若来源接口改变，运维可设置 `READER_EXTENSION_CAPTURE=false` 并使服务读取新环境：禁止新采集，**保留资料侧栏、已接收的任务、手动 ZIP 和 Context 导出**。要停用整个设备面，清空 `READER_EXTENSION_IDS`。

## 两条日常路径

| 任务 | 行为 |
|---|---|
| 找资料 | 工具栏打开原生侧面板；普通网页不注入脚本。搜索对话或登记的附件，可按项目浏览。点标题**直接打开 Reader 新标签**，不在插件内重复展示正文；文件链接定位到 Reader 文件面板。 |
| 整理 | 对话「更多」里移动到项目、设置全局或项目内置顶；文件「更多」只改显示名，不改原始字节。不授予删除、分享、源编辑或管理能力。 |
| 导入 | 首次确认目的地后只点一次。正在读取、已上传、服务端处理中和**已存入 Reader**是不同状态。若读取时关闭来源页，可从来源重新保存；服务端已接收则继续处理。若上传结果不明，先查原请求回执。 |
| 接续上下文 | 在侧面板点对话旁的「导出上下文」，或在 Reader 正文「更多」的导出项旁点 **导出上下文 `.context.zip`**。不需要经过导出向导；要细调才用原导出面板。在导出预设里可选两端共用的默认 Context 预设；失效预设阻止生成。默认完整对话、自动纳入已保存的接续信息、附件仅元数据。包可含个人批注和笔记；**只下载，不传回 ChatGPT**。 |

同源对话再次保存时：完全相同返回原件；只有已绑定、未改写的可验证树路径才能追加。不能证明安全（包括已归档、已删除、本地改过正文或附件、分支不同、旧手动导入身份不足）时，不动原件，可以另存。追加到**仍有效的整条实时分享**前要单独确认，worker 落库时再查一次。推断不到项目/账号全量清单，所以不提供「导入整个账号」或「导入整个项目」。

## 实现合同

* **账号**：一次性授权码（2 分钟）+ S256 PKCE + `state` + 固定公开扩展 ID / HTTPS 回调。设备 access 有效 10 分钟，refresh 单次轮换、有 30 天绝对期限。服务端仅存绑定实例密钥的摘要；禁用账号、凭据版本变化、撤销或实例密钥轮换都会拒绝。只有专用 `/api/extension/v1/` 接受设备 bearer；Cookie 不替代 bearer，设备 bearer 也不授权普通 Web API。所有数据操作由服务端按真实 `user_id` 校验；根管理员设备也没有管理权限。
* **浏览器**：来源脚本仅在当前对话接受真实点击；不读普通网页、浏览历史、Cookie 库，不同步凭据。页内只知道当前传输的票据（绑定标签、文档、路径和设备）。有权限的扩展上下文连接构建时固定的 Reader。来源会话和原始响应不进入 ZIP、Reader、设备任务账本或日志。不会自动过滤用户自己写进正文的隐私内容。公开扩展 ID 不是对本地安装包的签名：只安装可信构建。
* **打包与内存**：复用 Fork 的可见分支解析、分页去重和资源识别；可用的静态 Markdown 保留，不可还原的卡片/资源须复核。源附件按件读取，在内存小或容量未知时一次一件，条件允许最多两件；向扩展私有临时目录逐块发送并等接收确认，不把整个 ZIP 转成 Base64。beta 限额：单次 JSON 响应 8 MiB、累计 32 MiB、单个资源 16 MiB、采集内容与索引开销约 100 MiB、单消息正文 2 MiB。另受 OPFS、服务端 ZIP 限额及实际可用空间约束；不是无限大文件导入器。
* **Reader ZIP**：根部 `conversation.md`、`manifest.json`、逐行 `reader/source.jsonl`、以及声明的 `assets/`。按 UTF-8 **字节**范围和 SHA-256 校验正文，不以标题行推断消息；树来源记录源消息 ID、相邻展示消息和真实树节点段。列表来源不冒充树。资源按固定 256 KiB 块计算链式 SHA-256；验证成员集合、大小边界、正文中的引用、字节和每条消息的资源归属。另走原归档目录安全、资源扫描及 canonical 持久化。普通／低内存导入用同一协议；旧格式仍走原路径。
* **提交与恢复**：共用原有上传收据、分析任务、单 worker、资源等待和原子提交。用户＋来源绑定、PG 事务锁、canonical 状态及分享状态决定行为。审阅收据同时绑定制品、目标项目和分类版本；完全相同的竞态是无写入操作。后台不按名称合并、不覆盖批注/书签/接续笔记或已有项目。任务终态才显示保存成功。来源资料**不是**远端内容真实性的数字签名。
* **备份**：物理 PG 备份包含新增表；恢复到另一个实例时须在对外开放前轮换实例密钥并重新登记可信客户端。个人/系统逻辑 `.cr` 的显式业务表清单不导出设备授权，不视为设备绑定的备份。逻辑恢复若失去来源绑定，不按标题认领旧对话；原件优先保全。

## 发布边界与后续

P0–P2 是私有内测范围。P3/P4 **没有实现远端项目/账号枚举**，能力接口明确返回 `false`。下一阶段先用单独授权的测试账号验证项目标识、分页终点、失权与平台适用条件；不能证明完整时只展示用户实际选中的内容。必要时可增加本地选择用户自行取得的数据导出包，不把未选择的对话送上服务器。正式发布前须重新验证真实来源、安装／分发渠道和完整 CI。不要为了验证去访问真实用户资料或在生产演练。
