# Reader 正文媒体区域阅读流畅性复审

日期：2026-11-19。范围仅限 Reader 正文自然滚动、虚拟块测量、图片/公式混排和跨轮加载；基于当前代码与隔离合成内容的本地真实浏览器测试。未访问生产实例、真实对话或 GitHub 网页。

## 证据与限制

- 在独立 PostgreSQL、合成对话及本机 Chromium/Edge 中记录真实 wheel/touch 输入下同一正文块的逐帧位置；证据记录只留几何标量，不含对话正文、会话标识或凭据。
- 纯图片滚动的既有基线未出现同类反向跳动；公式虚拟长段出现相邻行累计间距不符、单帧反向移动；图片与公式混排的跨页定位也曾出现目标往返摆动。
- 一次跨轮加载基线记录到最多 623 CSS px 的单帧反向补偿，与页面先提交、随后等待测量再恢复锚点的时序一致。
- 首轮复核发现矩阵中的“长图”夹具实际上只有 680×940；该轮结果没有被当成真实长图验收。最终复测前已修正为 240×4000，并断言上传尺寸、折叠态和浏览器自然高度，随后纳入 10 项矩阵。
- 现有基线支持公式行几何与延迟锚点恢复是可复现根因；修复后的真实长图场景通过，但这只能说明该场景在验收中未复现跳动，不能证明图片本身就是用户环境里的唯一触发条件。

## 发现

### 高｜公式的外边距逃逸虚拟行测量框

虚拟行测量其边框高度并缓存给虚拟器，但 KaTeX 的垂直外边距可在普通块格式上下文中折叠到测量框之外。公式行重新挂载后，实际自然流间距与缓存高度偏离，反复越过虚拟化窗口时误差叠加，滚动纠正会与用户手势竞争，造成文字闪烁、上滑被拉回。

相关实现：`apps/web/features/conversations/assistant-message-renderer.tsx` 的 `VirtualBlockRow`；共享滚动锚点约束见 `docs/system/IMAGE_READING_STABILITY_CONTRACT.md`。

修复：`VirtualBlockRow` 建立独立格式上下文（`flow-root`），让 KaTeX 的上下外边距落在虚拟器实际测量的行盒内。

### 高｜跨轮内容先绘制、稍后才恢复锚点

旧边缘分页路径在更新已加载轮次后，等待虚拟目标挂载/测量，再执行锚点补偿。该窗口让新内容及重排先被绘制，用户可能看到大跳跃；稍后补偿又会将相同目标拖回。基线逐帧数据中最多 623px 的反向移动与此时序吻合。

相关实现：`apps/web/features/conversations/conversation-reader.tsx` 的边缘分页提交与 `reading-viewport.ts` 锚点归属。

修复：边缘分页先取得真实块锚点 lease，await 后重新捕获并校验；再用一次同步提交合并新轮次并恢复锚点。期间出现新滚动意图、导航或 Viewer 锁定则放弃旧补偿，不以陈旧 `scrollTop` 覆盖手势，也不启动第二套恢复循环。

### 中｜虚拟图片初始宽度可能污染首次测量

图片组件以前使用固定 320px 作为虚拟行初始宽度；真实阅读栏更宽时，图片首帧折叠高度及行高可能先按错误宽度计算，随后才被布局测量修正。该路径是媒体行几何不稳定的独立风险，但现有纯图片基线没有证明它单独造成用户所述跳动。

相关实现：`apps/web/features/attachments/image-presentation.ts` 的 `useImageLane` 与虚拟列表宽度提供者。

修复：虚拟列表向图片组件提供当前阅读栏宽度，虚拟图片 remount 不再统一从 320px 估高；现有 ResizeObserver 与共享几何 owner 继续负责后续真实尺寸变化。

## 候选修复复验

- 当前代码：公式测量盒修正在 `apps/web/features/conversations/assistant-message-renderer.tsx`；图片 lane 宽度修正在 `apps/web/features/attachments/image-presentation.ts`；跨轮锚点提交修正在 `apps/web/features/conversations/conversation-reader.tsx`。Reader 根滚动区禁用浏览器原生 scroll anchoring，共享 `reading-viewport.ts` 是唯一异步几何补偿 owner；没有叠加 image-specific scroll loop。
- 真实 Chromium/Edge 浏览器 + 合成数据：10/10 个桌面 1280px wheel 和手机 375px touch 案例通过，包含真正的 240×4000 长图（并断言其折叠态）、短图、长公式、图文公式混排及跨轮加载。每帧追踪同一个真实 DOM block，并校验确有媒体请求、公式、边缘加载及新轮次挂载。
- 保留的10份脱敏几何 trace：最高单帧逆向位移 **0px**、累计逆向 **0px**、相邻虚拟行未测间隙 **0px**、可见空帧 **0**；最小真实手势行进 **201px**。此前同机同类基线的公式场景分别出现最多 **16.5px** 单帧逆向、**32.5px** 累计逆向和 **8.5px** 行间隙；边缘加载场景最多 **623px** 单帧逆向。
- 既有 Reader/Share/Offline/Compare 稳定性及图像折叠套件：28/28 通过；与上面的新增媒体运动矩阵分开计数。
- 仓库 lint、typecheck、Web production build 均通过。测试使用隔离本机服务及合成对话；没有访问或操作生产实例，代码仍是未发布工作树。该验证不替代生产部署、真实设备验收或用户产品验收。

## 复审验收

实现后用合成短图、真正超长图、长公式、图文公式混排及跨轮加载，分别在 375px 触屏和 1280px 桌面通过慢速原生输入双向往返；记录同一真实 DOM 块的逐帧位移、虚拟行间距与分页边界。成功标准是行间隙不再偏离缓存几何、可见正文无丢帧/空窗、单帧逆向移动不超过 2px、完整手势反向累计不超过 4px。测试未覆盖的真实设备/生产行为继续标记为未验证。
