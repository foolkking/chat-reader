## 实测

| 检查 | 观测 |
|---|---|
| 浏览器与权限 | Chrome for Testing `151.0.7922.34`、Edge `158.0.4370.33` 实际加载 MV3。验证真实授权窗口、确切回调、工具栏行为和原生 `SIDE_PANEL` 上下文。Chrome 还从未登录状态经过 Reader 登录返回授权；之后清空网页 Cookie、关闭 Reader 标签页，两端仍能操作。 |
| 导入与完整性 | 首次 3 条（含相邻助手、代码中的伪标题和公式），重复保存仍为同一对话，纯尾部变为 4 条，改写分支则停在复核。两浏览器分别独立读回 PG：4 条消息、4 条来源引用、两个文件的落盘摘要及消息归属都正确。夹具含 **8×2048 PNG** 和 **770,011 字节 CSV**，不代表最大容量。逐项检查实际接收的合成 ZIP 中没有来源会话测试标记。 |
| 资料与接续 | 未归类搜索、移动后原项目不再命中、目标项目置顶、文件显示名修改和文件定位。点标题打开新 Reader 标签。插件和网页分别生成并下载真实 Context ZIP，查验 CRC 与 canonical 成员；不是改名后的导入包。 |
| 失败恢复 | 实际关闭来源页后显示「未发送」；浏览器 OPFS quota 限制造成空间不足，旧数据不动；断开文件下载须复核。隔离 worker 停止、关来源页、重载侧面板再启动 worker，原收据完成。另在测试扩展自己的 offscreen 文档注入一次故障：丢弃已成功的 201 响应，查原回执恢复到同一对话，未重新上传。 |
| 用户隔离 | 两个不同 Reader 用户，检查跨账号列表、改名、置顶、移动、任务和制品下载；普通 Web Cookie/设备 bearer 不可互换。复查授权码单次使用、refresh 轮换、撤销与实例密钥轮换；任务排队后撤权不能落库。已确认但尚未写入时新增实时分享，也不能绕过二次确认。 |
| UI | 对扩展文档截取 320、375、480 CSS px，分别覆盖中/英文、浅/深色，断言没有横向溢出。用浏览器 IME composition 与 Tab 验证输入和焦点；不是物理输入法或手机真机测试。截图在限定宽度的扩展页面生成，**原生侧栏单独验证**，不伪装为桌面外壳截图。 |

## 运行结果和保留的失败记录

- Reader：七个相关测试文件 **136 通过、2 跳过**（Windows 环境无 symlink 权限），另有 **1 个**由固定 Fork 直接生成的黄金样本测试通过。提交后重新运行完整 `test_reader_extension.py` **12/12**，有重叠，不重复计数。真实 PostgreSQL 迁移往返、单 head 及 Context 专项 **14/14**；仅 Alembic 既有 `prepend_sys_path` 提示。
- Fork：Node `24.22.3`，原有套件加 Reader 合同共 **176** 项，**113 通过、63 跳过、0 失败**；显式指定 Chrome 后核实所有跳过均缺上游私有夹具。未索取这些资料、未放宽断言。最初缺 `jsdom`，系统 Node 20 也不支持上游 `--test-force-exit`；按锁文件安装依赖、换兼容 Node 后重跑。
- Web：仓库 lint、typecheck、Next 生产 `build --webpack` 通过。本轮不是整个 Reader 的远端 CI 或全量浏览器回归。
- 早期原生测试暴露配置解码、worker 领取夹具及 SQLite 重复提交时的无意义进度写入；另有一个造数夹具只给一条消息，违反现有「用户＋助手」创建合同。均修正原因，未扩大权限。双账号测试最后还发现：跨账号更名已被拒绝，但既有路由错误地返回 500；修为与不存在资源相同的 **404**，再跑完整矩阵。
- 第一种“丢失回执”注入只截到页面网络、没有实际截到 offscreen 请求，该次断言失败，不算通过。一次重启演练也未在时限内进入预期终态；当时目录仍在变更，未将原因推断成生产故障。冻结源代码并重启隔离 API/worker，改为验证**实际 201 后**的故障注入，最终两个浏览器回执均通过。
- 本机安装 ZIP `chat-reader-0.1.0-localhost.zip` 仅绑定 `http://127.0.0.1:18383`，25 个成员、97,344 字节，SHA-256 `601647e79a4ccfc00ad9f4d392e5fed84b5f69ac87f477530d77fdb018e6c787`。最初用 Windows 路径排序与 ZIP 字符串排序比较导致清单断言失败；最终按**完整集合、成员数量、每个成员的实际字节和 CRC**独立读回，不靠顺序。
