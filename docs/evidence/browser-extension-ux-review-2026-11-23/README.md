## 怎样复现

1. 使用仅供本机演练的独立目录，按[隔离实验说明](../../../scripts/extension-beta/README.md)准备临时环境变量、合成账号、网络隔离、PG/NGINX/API/worker 和 Web；不得用已登录浏览器、生产镜像配置或已有用户资料。当 API 依赖镜像与源码分开取得时，将**本次固定 Reader 修订**的 `apps/api/app`、`apps/api/alembic` 只读映射到两项测试服务中的 `/app/app`、`/app/alembic`，并核验实际挂载。测试数据库使用 tmpfs。固定 Reader `4afb430cf6d5d03b67474cd8a8d9e5ec2021935c`、Fork `a3f0ebe738a2e69ea5c866bdddb29ce119f08fc5`，两者均不需另建分支；可用 `git archive` 导出到任务临时目录。Web 依赖和构建也用隔离副本。
2. 在临时 Fork 执行 `node scripts/package-reader.cjs http://127.0.0.1:18383 <任务目录下的扩展目录>`。浏览器使用显式 Chrome/Edge 可执行文件、全新 profile。保留实验要求的外部 DNS 阻断，来源用原脚本的合成响应；不访问真实 ChatGPT。若复制了上一轮测试包，不要认作同一制品：本轮用 Git 对象重建，与此前 loopback ZIP 的 25 个成员同名，**原始字节比较未通过**（12 个文本成员不同），仅规范 CRLF/LF 后全部相同。
3. 附加探针仅适用于该基线。先在**临时 Reader 副本**运行 `git apply --check <baseline-observations.patch 的绝对路径>`，再在该临时副本应用。它只修改测试驱动，不修改扩展或服务。按原说明在副本中提供 Playwright 依赖，然后分别运行 `node scripts/extension-beta/browser.cjs <浏览器> <扩展目录> <任务临时目录> <未使用过的英文标签>`。例如 `chrome-zh-ux-check`、`edge-en-ux-check`。发布的探针含两轮的观察项；原始 Chrome 轮未做 Edge 特有的两个附加场景，机器回执按实际发生记录。不要将两次各 14 个原流程步骤解释为 28 个独立新门禁。
4. **人工复核顺序：**首次目的地为未归类；从页面保存，等后端提交后观察按钮；重复、追加、制造分歧，在侧栏测搜索框与首行距顶端。随后将对话移入已建项目 P，原默认值不动，重存原版本，核实是同一 ID 且项目仍为 P；在「文件」及按名称的「对话」搜索比较同一附件的展示。在新的合成来源制造单个文件下载失败，经复核选择保存可用内容，比较警告计数与最后的提示。导出则分别从侧栏、Reader 页面下载，检查 ZIP 的实际成员。失败时保留相关步骤，不记录标识符、URL 查询、请求头、临时账号或源正文。
5. 结束后只停止本批次服务；不要删除 Docker volume 或清空公共临时目录。本轮核实 18383–18385 已无监听、审查 Compose 项目剩余容器为 0、临时服务凭据文件已移除。两份隔离合成浏览器 profile 的递归清理被本机策略拒绝，未绕过；它们仍在任务临时目录，不属于交付物。这里仅保留脱敏回执、观察补丁、四幅截图，不保存 profile、导入包或 `.env`。

未验证：真实上游账户、真实官方数据 ZIP、整浏览器退出并重启后的恢复、物理输入法、远程 CI 和生产状态。本报告对这些项目均不提供通过证明。
