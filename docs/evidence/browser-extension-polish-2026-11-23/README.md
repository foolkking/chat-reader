## 侧栏补测：找不到时不丢搜索，写入不重复

同一份仅供本机的安装包，在中文 Chrome 151.0.7922.34 和英文 Edge 158.0.4370.33 各走完 28 个步骤，两个进程均退出 0。设备授权、侧栏、Reader 数据库、worker、下载和进程重启是实际操作；来源网页、用户数据和故障均为隔离夹具。[机器回执](catalog-recovery.json)含工作树/安装包指纹、逐项观测、失败尝试及实际完成时间。

## 如何复核

1. 用[隔离实验说明](../../../scripts/extension-beta/README.md)创建新的、仅监听本机的 NGINX、Next、FastAPI、PostgreSQL 16 和 640 MiB worker。两个桌面浏览器均使用各自全新的 profile；来源响应是测试夹具，DNS 阻断公网。设备授权窗口、数据库事务、文件、下载和实际原生 `SIDE_PANEL` 不是模拟。不要使用个人资料、真实对话或生产配置。
2. 在两个**现有** `codex/reader-extension` 工作树使用匹配的产品代码。构建精确绑定 `http://127.0.0.1:18383` 的私有安装目录。在 Reader 分别运行 `node scripts/extension-beta/browser.cjs <浏览器> <同一扩展目录> <批准的临时根> <新标签>`，中文标签含 `zh`；故障标签含 `faults`，两者串行运行。CSS 坐标与截图在限定宽度的真实扩展文档测量，打开原生侧栏单独断言。检查保存／导航时使用可访问名称和真实点击，不直接调用按钮回调。
3. Reader 从 `apps/api` 运行 `python -m pytest -q tests/test_reader_extension.py tests/test_grouped_search.py` 及回执中列出的 Context／旧官方格式专项；Fork 用 Node 24 运行 `npm test`。使用当前任务独立 `TEMP`、`TMP` 和 pytest `--basetemp`，保留未提供私有上游夹具所致的 skips。Reader Web 生产构建、lint、typecheck 与 CI 分片登记的局部验证不等于全量 GitHub CI。

## 失败也是证据

- 提前于网关就绪的尝试没有通过登录，不计入验收。文件名也能出现在正文 Markdown 链接；仅查看搜索引擎的第一种命中类型曾丢失合法的“附件匹配”。现在保留原排序，再核对当前页实际关联的有效附件；不会把文件当成独立条目。
- Reader 文件面板最后一行的浮动操作菜单曾被滚动容器裁切；另有测试选到了响应式的隐藏副本。分别修正菜单布局和可见目标，再用真实操作验证重命名与下载。没有去掉原权限断言。
- 早期临时空间失败回测点了已经代表“查看问题”的主按钮。改成明确的“检查并保存当前版本”；保留缺空间、正文超限和上传数不增加的断言。
- 早期一轮部分保存只在侧栏更新，回到来源页时仍是旧状态。随后把“返回当前标签”纳入回执刷新。之后将来源初态改成“核对中”又暴露出独立问题：同文档导航时，浏览器记录的消息发送者文档 URL 可能仍是旧的，当前标签 URL 已经更新。这使旧 UI 的初始“保存”看起来正确，却并非一次可靠的来源检查。单列失败并验证当前标签、确切文档和路径，不用延时或标题匹配绕过校验。
- 行末按钮的可访问名称从重复的“更多”变为“更多：对话标题”后，旧的精确名称定位失败。回归改成核对**完整名称及正确的对话**，没有仅按第一个按钮猜测。
- 回执保留各次尝试的标签、阶段与结果。真实官方 ZIP、实体输入法／屏幕阅读器、用户真账号、线上 GitHub 和生产环境**不由这些测试证明**。私有 beta 不是正式发布；[批量导入只做授权样本评估](../../planning/reader-extension-batch-sample-gate-2026-11-23.md)。
