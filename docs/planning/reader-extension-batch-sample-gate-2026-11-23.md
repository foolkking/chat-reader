# 官方导出包：先验证能证明什么，再决定是否做批量导入

本轮不加项目／账号导入按钮，不改变旧上传入口。没有取得获准的真实官方包；表中是待核验的问题，不是对官方 ZIP 格式或平台许可的断言。

| 要回答的问题 | 最小测试样本／判据 | 信息缺失时怎么做 |
|---|---|---|
| 是否读全用户选的内容？ | 用专用测试账号建一条项目外、两条项目内对话，人工记下预期条数；含非 ASCII 文本、连续同角色消息及可区别的测试附件。先在本地只读查看归档目录结构，逐项核对，识别分片、重复或缺页。 | 可说明“本包可识别 N 条”，不能显示“已找到全部账号对话”。 |
| 是否知道当前分支？ | 制造一处分歧，人工指定期望叶节点；核对主路径、隐藏节点、源 ID 和顺序，不以最后修改时间选分支。 | 标明无法确定；由用户选择或跳过，不自动追加。 |
| 项目归属能否可靠还原？ | 两个同名但实际不同的项目，另有一条已移动的对话。验证稳定项目身份、项目成员指向、独立的会话身份与导出时点。 | “项目未知”不是“未归类”。只允许显式选择 Reader 目标，不按项目名合并，不移动已有原件。 |
| 附件或互动内容真的在包里吗？ | 人工对照有字节／仅引用／缺失三种，以及一个有静态替代的互动项；核对文件摘要与所属消息。 | 不对外联网补抓；逐项说明缺件，需同意才部分保存。 |
| 能否安全选取少数资料？ | 先在本地生成只含计数和状态的预览。选一条时，核对其他对话、账号资料、附件没有进入上传、日志或证据。做有界读取、取消、空间不足和 640 MiB worker 测试。 | 未证明有界、归属或完整性前，不进入发布计划。不接收真实用户全量导出作为测试数据。 |

**现有证据。** [现有解析器](../../apps/api/app/services/import_pipeline/official_json_parser.py)能识别对象／数组及 `mapping/current_node`；这不证明大型 ZIP 能流式读取，也不证明项目清单或附件齐全。[既有入口回归](../../apps/api/tests/test_canonical_persistence_official.py)验证旧 `/api/imports/preview` 对合成单条和数组仍返回 `422 unsupported_source_profile`，没有把禁用当作成功导入。合成输入只验证代码，不代替真实格式、真实归属或适用条款。

**下一步交付判据。** 若用户愿意，用专用账号自行取得最小无敏感样本，并明确授权本机只读分析；不提供账号、登录凭据或个人历史。按表逐项输出“实测支持／不支持／未知”和聚合计数，不将样本或记录 ID 放入仓库。取得样本不等于获准自动枚举平台；仍须确认适用条件。能证明的数据才在 Reader Web 提供“预览 → 选择 → 导入”，每条沿用现有授权、来源校验及可恢复收据。侧栏最多提供入口，不新设任务中心。

**可以只交本地路径，不上传 ZIP。** 准备一个专用测试账号的小包：两个项目各一条，加一条项目外测试对话；其中一条有分支，一条带无敏感的小附件。人工记下预期归属和当前分支，最好两个项目或对话同名。无需交付真实账号、密码、Cookie 或个人历史。可选的第一步是在本机运行 `python scripts/extension-beta/inspect_project_sample.py --dedicated-test-export "<小测试包路径>"`：仅读取明确命名的对话 JSON，输出聚合计数，不联网、不解压落盘、不读媒体或打印标题和 ID。`project_id` 只算候选线索，`gizmo_id` 不算项目；没有识别到清单会报未支持，而不是报告“没有项目”。**仅靠该报告不能通过真实归属、分支和附件验收。**
