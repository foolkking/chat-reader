## 已确认范围与设计选择

- 用户明确允许服务器备份只保留最新两份，删除之前备份。该授权取代此前“服务器备份也不改”的保守解释；线上数据库、导入原件、附件、个人资料继续受保护。
- 用户要求导出文件关闭后或三分钟后回收，并提出管理员控制。采用推荐组合：Root Admin 管理保留时长，默认 **3 分钟**；默认开启关闭后提前释放。
- 用户同意修复过期导出回收、限制备份数量、减少重复存储并保留必要恢复能力。
- 不增加定期备份、备份提醒或用户配额。发布镜像只使用 GitHub CI 的已验证产物，不在本机或 King 构建。
- 用户明确选择暂不设置异地副本；本轮不配置外部存储、不上传备份，也不以此阻塞交付。

## 一、用户导出流程

服务器临时导出文件自生成并提交成功开始计时，默认 180 秒。排队和生成时间不计入。
正常状态在下载按钮附近用一行小字表示“临时下载，保留 3 分钟”；不新增弹窗、常驻说明卡或紧迫倒计时。

| 事件 | 服务器行为 | 用户结果与恢复 |
|---|---|---|
| 导出完成 | 持久化实际到期时间、适用策略版本及重建所需的原导出选项 | 下载按钮可用，重新打开面板读取真实状态 |
| 用户开始下载 | 在发送文件前取得有效的下载占用；先检查用户、任务、到期与文件状态 | 下载进行中不因面板关闭或三分钟到期被中断 |
| 用户明确关闭导出面板 | 释放当前使用会话并请求提前回收；没有其他有效使用者、排队下载或活动下载时才回收 | 已保存到用户设备的文件不受影响；尚在生成的任务不被关闭动作取消 |
| 另一个标签页正在使用同一结果 | 在原有效期内保护该使用会话；关闭一个页面不删除另一页面正在领取或下载的文件 | 页面读取服务端实际状态，不显示虚假的可下载按钮 |
| 浏览器退出、崩溃或断网 | 关闭通知仅为尽力发送；服务端到期回收独立生效 | 不要求用户必须正常退出才能释放空间 |
| 切换标签页、失焦、隐藏页面、普通重渲染 | 不作为明确关闭动作，不直接删除文件 | 回到页面可继续操作；停留、悬浮或反复查询不会无限延长到期时间 |
| 已到期且无活动下载 | 标记待回收并停止新的下载；健康运行下下一次有界清理处理物理文件 | 显示“临时文件已清理，重新生成”，保留导出选项和 Skill 操作 |
| 到期时正在下载 | 拒绝新的下载领取，现有传输继续；完成或断开后释放占用 | 大文件或慢网络仍可下载；失败重试可重新生成 |
| 回收失败 | 保留失败状态和重试时间，有限退避；物理回收成功后才标记完成 | 用户仍可重新生成，不把“请求已发送”显示成“空间已释放” |

关闭通知由显式关闭/离开路径触发，不以组件任意卸载代替。下载领取和提前释放必须原子协调，
避免“点击下载后立刻关闭”时删除尚未开始读取的文件。下载占用在响应生命周期结束时释放；
服务崩溃遗留占用有可恢复期限，不能无限保护已失联文件。

文件有效期不会因页面仍然打开而超过管理员指定的时长；只有已开始的实际下载可延长物理保留。
多标签页使用会话只能在这个截止时间内保护提前释放，不是永久续期。

## 二、管理员设置

复用设置中的“功能与默认值”，增加一个紧凑的导出分组：

- **临时导出保留时间**：默认 3 分钟；建议范围 1–60 分钟。
- **关闭导出面板后提前清理**：默认开启，实际回收仍遵守下载占用保护。

只允许 Root Admin 修改，后端校验范围、记录脱敏审计，失败保留输入。普通用户从能力/任务响应
读取实际生效值，不请求管理员接口。修改只改变新生成的导出，已有结果按其记录的到期时间处理。
旧客户端未提交新字段时不得重置策略。既有历史过期产物作为单独、已授权的迁移清理批次处理。

## 三、适用范围与数据边界

适用：服务器持久化的 Context Package、带附件的 Markdown/CanJSON 包、附件批量 ZIP、
个人/系统 `.cr` **导出结果**。下载完成的用户本地副本不受服务器回收影响。

以下不应用三分钟策略：

- PostgreSQL、导入原文、附件对象、Current/Index 保存版本、个人/系统 Skill Bundle。
- 当前服务端离线副本和浏览器离线资料；只回收临时交付文件，不把现有离线保留合同改成三分钟。
- `.cr` 恢复预检上传及被恢复任务占用的输入；它们虽然也使用 ExportArtifact，仍走恢复生命周期。
- Share 内容与授权、服务器部署恢复备份，以及没有持久化中间文件的直接流式导出。

导出面板、维护准备、附件下载、个人/系统备份完成页和任务中心共用实际产物状态。
重建沿用原选项和本人范围，产生新的任务尝试；若原对话已变更，明确使用当前版本，不伪造旧快照。
切换账户立即结束前端使用会话；所有状态、领取、释放和重建接口逐次核验账户权限。

## 四、服务端实现边界

- 在现有 ExportArtifact/BackgroundJob 和 worker 生命周期中增加到期、待回收、已回收及失败重试状态，保留轻量任务结果用于重入。
- 不直接移除数据库仍然引用的文件。先用短事务锁定产物、复核到期/占用/权限并声明回收，再删除确切文件，最后确认完成。失败可重试，重复执行幂等。
- 文件访问与回收使用同一并发边界，涵盖领取后尚未开始读取、流式传输、Range 请求、客户端断开和进程中断。
- 增加专门的过期导出类别，不把全局 24 小时 orphan grace 降为三分钟，不扩大为导入/附件/离线数据自动清理。
- 清理采用现有 worker 的有界维护机制。正常运行下目标为到期后 30 秒内处理可释放文件；不得简单排到大型导入任务后，造成长时间只过期、不删文件。健康与存储报告显示积压和失败。
- 日志只保留原因码、计数和字节数；不记录对话正文、文件名、用户业务标识或令牌。
- 历史清理先扫描、核验产物归属与实际引用，再逐项回收；已观察的 55 个过期结果不作为永远不变的删除清单。

## 五、服务器备份只保留两份

镜像上传、重复上传或加载重试本身不触发数据备份。真正迁移/替换服务前，按现有一致性流程生成
一次恢复快照。不能因为本轮已备份就复用期间发生过业务写入的旧快照。

新备份写入临时目录，完成数据库和四个归档校验后才成为正式备份。发布验收成功后，按生成时间
保留最新两份正式、已验证备份，清理更早的完整备份。生成/发布失败时先保留旧恢复点，不能提前
删旧备份给失败的新备份腾位；稳定状态目标为两份，验证期间可短暂多一份。

保留数量不再叠加“最近 30 天全部保留”，也不默认无限累积迁移基线。报告区分正式备份、未完成
临时目录和未知目录；未知文件不自动删除。清理仅作用 `/opt/chat-reader/backups` 中确认的备份目录。
修复保留报告在主机 Python 3.6 下不能运行的问题，采用明确支持的运行方式；不更换服务器系统 Python。

先修复过期导出回收，减少之后每份备份的体积；过渡阶段继续保留五组件备份/恢复合同。
后续对可再生交付物分层、未变化大对象去重复用，必须一起适配 manifest、引用及恢复验证。
两份逻辑快照共享对象时不能宣称是两份独立物理恢复副本；本轮暂不设置异地副本。
