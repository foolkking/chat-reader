## 第一批：产品定位与改造边界

### D-001 系统定位
- **问题：** 系统长期定位是保持工具型，还是扩展为知识管理/在线 AI 产品？
- **当前事实：** Chat Reader 是 ChatGPT 导出资料的阅读管理系统，无账号/在线生成/多用户。
- **用户最终决定：** **保持工具型定位**。不加账号、不加在线 AI 对话、不做多用户。继续 `local:default` 单主体 + Share 访客双身份。
- **影响模块：** 全局产品边界。

### D-002 技术边界
- **问题：** 本轮是否允许改后端和数据库？
- **用户最终决定：** **前后端协同改造**。允许改 API、DB 表结构（Alembic migration）、数据协议、Dexie schema、Service Worker。
- **影响模块：** 后端、DB、离线协议。

### D-003 视觉方向
- **问题：** 全面重构视觉交互，还是保持现有风格？
- **用户最终决定：** **结构化渐进**。保留布局框架和导航结构，重做视觉语言，可微调主色。
- **影响模块：** 设计系统、全部页面样式。

### D-004 端侧优先
- **问题：** 桌面端和移动端优先关系？
- **用户最终决定：** **桌面优先**。桌面实现完整功能与最佳体验，移动端保基本可用、聚焦阅读。
- **影响模块：** 响应式策略、移动端方案。

### D-005 离线能力地位
- **问题：** `/library` 离线是否进入主导航？
- **用户最终决定：** **情景化引导**。不入主导航，通过情景化提示引导发现，保持主导航简洁。
- **影响模块：** 信息架构、离线入口。

## 第二批：信息架构与核心流程

### D-006 首页职责
- **问题：** 首页 `/` 承担什么职责？
- **可选方案：** A 资料总览中心 / B 继续阅读中心 / C 混合仪表盘。
- **用户最终决定：** **方案 A 资料总览中心**。显示全部对话和 Project，提供导入/搜索/管理入口，侧栏顶部增加"最近"快速入口。
- **影响模块：** `/` 首页、app-shell、project-sidebar。

### D-007 对话/Project/最近关系
- **可选方案：** A 平级导航 / B 嵌套层级 / C 智能合并。
- **用户最终决定：** **方案 B 嵌套层级 + 将 `/recent` 正式加入导航**。保持"对话/项目"标签切换框架，侧栏顶部增加"最近"入口，"已归档"保持独立。
- **影响模块：** project-sidebar、`/recent`、导航。

### D-008 搜索地位
- **可选方案：** A 保持侧栏按钮 / B 提升一级导航 / C 侧栏顶部搜索框。
- **用户最终决定：** **方案 A 保持当前 + 优化可见性**。侧栏按钮不占主导航，增加全局快捷键 Cmd/Ctrl+K。
- **影响模块：** sidebar-search、search-box、shortcut-manager。

### D-009 主要进入 Reader 路径
- **可选方案：** A 列表驱动 / B 搜索驱动 / C 继续阅读驱动 / D 混合路径。
- **用户最终决定：** **方案 D 混合路径**。列表、搜索、继续阅读三条路径都优化，重点优化路径衔接。
- **影响模块：** 列表项、搜索结果、reading。

### D-010 全局批注/笔记中心
- **可选方案：** A 保持 Reader 内 / B 全局只读视图 / C 演进知识中心。
- **用户最终决定：** **方案 A 保持当前**。批注和笔记继续作为 Reader 内功能，不做全局中心。搜索范围可包含批注内容。
- **影响模块：** annotations、search。

## 第三批：Reader 阅读体验

### D-011 Reader 整体定位
- **可选方案：** A 极简沉浸 / B 功能工作台 / C 渐进式显示。
- **用户最终决定：** **方案 C 渐进式显示**。默认正文 + 章节 TOC（右）+ 对话 TOC（左 rail）；支持专注模式一键隐藏辅助；支持工作台模式按需展开并记忆。
- **影响模块：** conversation-reader、reader-frame。

### D-012 正文布局
- **可选方案：** A user 右对齐 / B 统一左对齐 / C 混合布局。
- **用户最终决定：** **方案 B 统一左对齐（文档风格）**。所有消息左对齐，通过头像/标签/背景色区分 user/assistant，最大宽度受阅读宽度设置控制。
- **影响模块：** message-item、assistant-message-renderer、globals.css。

### D-013 双 TOC
- **可选方案：** A 保留双 TOC / B 合并统一 / C 改变呈现。
- **用户最终决定：** **方案 A 保留双 TOC + 优化区分度**。对话 TOC = 跨消息导航（消息列表），章节 TOC = 消息内导航（章节目录）。优化命名与视觉区分。
- **影响模块：** conversation-index、conversation-toc。

### D-014 顶栏动作分级
- **可选方案：** A 扁平化 / B 分级显示 / C 情景化动态。
- **用户最终决定：** **方案 B 分级显示**。一级（当前对话搜索/阅读导航/批注/分享）+ 二级更多菜单（导出/在线离线切换/展开全部/同步）+ 编辑操作条件显示 + 消息级 hover 菜单。
- **影响模块：** reader-header-action-rail、conversation-action-menu。

### D-015 批注工作区形态
- **可选方案：** A 浮窗 / B 右侧 Dock / C 混合模式。
- **用户最终决定：** **方案 C 混合模式**。**默认浮窗**（覆盖正文区域，可拖动/调整大小/记忆位置）；提供"固定到左侧导航栏"选项——固定时**完全覆盖** Project 树/对话列表，不是标签切换，不取代任何 TOC；提供返回导航栏的入口。
- **补充约束（用户明确）：** 拆离、管理等具体工作都要考虑到；批注工作区是独立第四区域，与两个 TOC 并存不互相取代。
- **影响模块：** annotation-workspace、project-sidebar、conversation-reader。

### D-015-A 批注默认位置
- **用户最终决定：** **默认浮窗** + 提供"固定到左侧侧栏（覆盖之前的左侧栏内容）"选项。
- **关键布局澄清（用户截图确认）：**
  - 左侧导航栏 = 独立区域（Project 树 / 对话列表 / 搜索 / 导入 / 设置）。
  - **正文区域**包含三部分：对话 TOC（左 rail，彩条 + U/A 序号）+ 消息正文（居中）+ 章节 TOC（右，树状）。
  - **两个 TOC 都属于正文区域**；**没有独立右侧栏**，章节 TOC 占正文右侧。
  - 批注浮窗覆盖正文区域；固定时覆盖左侧导航栏。

## 第四批：移动端体验

### D-016 移动端功能范围
- **可选方案：** A 纯阅读 / B 阅读+轻量管理 / C 功能对等。
- **用户最终决定：** **方案 B 阅读 + 轻量管理**。支持阅读/导航/创建批注（简化版）/分享/导出/单个对话移动到 Project；不支持导入/编辑消息/批量操作/复杂 Project 管理。
- **影响模块：** 移动端全部组件。

### D-017 移动端 Reader 顶栏
- **可选方案：** A 极简 / B 平衡 / C 自适应。
- **用户最终决定：** **方案 A 极简 + 优化更多菜单**。顶栏：返回 + 标题 + 阅读导航 + 更多菜单；其余操作进更多菜单 Sheet。
- **影响模块：** mobile-reader-sheet、reader-header-action-rail。

### D-018 移动端继续阅读入口
- **可选方案：** A 与桌面一致 / B 首屏继续阅读卡片 / C 默认最近列表。
- **用户最终决定：** **方案 B 首屏继续阅读卡片**。移动端首页顶部横向 1-3 个继续阅读卡片（有进度条），下方保持对话/项目标签列表；无最近阅读时不显示卡片区。
- **影响模块：** 移动端首页、recent-items。

## 第五批：视觉系统

### D-019 整体气质
- **可选方案：** A 工具型极简 / B 现代阅读器 / C 知识工具。
- **用户最终决定：** **方案 B 现代阅读器（舒适温暖）**。参考 Readwise Reader、Matter、Pocket。温暖背景、柔和阴影圆角、优雅排版、强调阅读舒适度。
- **影响模块：** 设计系统全局。

### D-020 主色调
- **可选方案：** A 保持绿色微调 / B 换色系 / C 中性灰。
- **用户最终决定：** **方案 A 保持绿色系，微调更温暖**。主 accent 由 #0f8f70 → **#10a37f**；accent-soft → **#f0fdfa**（浅 teal）；深色模式 accent 保持 #55c9a6 附近，确保对比度。
- **影响模块：** globals.css CSS 变量。

### D-021 信息密度
- **可选方案：** A 紧凑 / B 舒适宽松 / C 用户可调。
- **用户最终决定：** **方案 B 舒适宽松 + 局部自适应**。正文区域宽松（消息间距 32px），侧栏适度紧凑（4-8px），对话 TOC 极紧凑（rail），阅读宽度保持 compact/standard/wide 三档。
- **影响模块：** globals.css、各列表组件。

### D-022 圆角阴影边框
- **可选方案：** A 锐利现代 / B 柔和温暖 / C 混合策略。
- **用户最终决定：** **方案 B 柔和温暖**。容器/按钮 8px 圆角，输入框 6px，对话框/Sheet 顶部 12px，代码块 6px；多层柔和阴影（subtle/soft/medium 三级）；边框主要用于输入框和分隔线，容器优先用阴影。
- **影响模块：** globals.css、组件样式。

## 第六批：边界与执行方式

### D-023 明确不做事项
- **用户最终决定：** ✅ 确认以下全部不做。
- **功能层面：** 不加注册/登录/账号；不加在线 AI 对话；不加多用户/权限；不加团队协作；不加全局批注/笔记中心；不加标签系统；不加日历/时间线视图；不加图片/附件上传（只渲染导入内容中的）；不加音视频播放器；不加 HTML/PDF 导出（保持 Markdown/JSON/.cr）。
- **技术层面：** 不实现真正虚拟滚动（保持窗口加载机制）；不重构微前端/多应用；不换主技术栈；不给 Reader 加 SSR（保持 CSR）。
- **体验层面：** 不彻底重构信息架构（保持 Project/对话基本关系）；不改导入 preview→commit 基本流程；不删除任何现有核心功能（编辑/版本/合并/拆分/Share/Export 等）。

### D-024 兼容性要求
- **问题：** 是否必须向后兼容旧数据和协议？
- **用户最终决定：** **不向后兼容仅适用于 CSS token（色值/间距/阴影等）和可能升级的 Dexie schema 版本。** 具体边界：
  - 不允许：删除 PostgreSQL 数据、破坏已有 Share URL、让已有离线包失效、丢失批注/笔记/阅读位置。
  - 允许：CSS 色值/间距/阴影等全局修改（纯视觉）；Dexie 版本升级可在 UI 提示后清空离线库重新下载。
  - 如果 Dexie 需要升级版本导致清空离线库，必须在 UI 明确提示（如首次进入 `/library` 时显示"数据格式已更新，请重新下载离线资料"）。
- **影响模块：** 数据协议、CSS 系统、Dexie。
- **封板补充：** 2026-07-27 封板核对时进一步将"不向后兼容"限定到具体范围。详见 `EXECUTION_LOCK.md §15`。
- **注意：** 执行时若破坏现有本地离线数据，需在 UI 明确提示用户重新准备。

### D-025 执行方式
- **用户最终决定：** **第二轮一次性完成全部已确认方案，不分 Phase**。本规划给出的实施顺序仅为执行内部的依赖顺序，不代表分期。
- **影响模块：** 执行节奏。
